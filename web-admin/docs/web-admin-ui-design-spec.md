# web-admin 管理后台 UI 设计规范

## 1. 文档目的

本规范不是抽象视觉建议，而是 `web-admin` 当前后台 UI 的实现标准。

目标只有一个：

- AI 或开发者仅根据本文档，就能直接实现出与当前 `/admin/users`、`/admin/roles` 页面一致的最终效果。

本文档优先级高于历史口头说明、临时截图备注和旧版草案。若页面实际实现与旧规范冲突，以当前已经确认的最终效果为准，并应反向更新本文档。

## 2. 适用范围

本文档适用于：

- `web-admin` 全部后台管理页面。
- 列表页。
- 详情、编辑、新增抽屉。
- 关联对象选择表格。
- 树形权限表格。
- 批量操作模式。
- 分页、局部加载、删除确认等通用交互。

本文档特别以以下页面作为标准样板：

- `/admin/users`
- `/admin/roles`

后续新页面若属于“用户、角色、资源、关联对象、权限树、日志”等同类后台场景，必须优先复用本文档的模式，而不是自行设计新样式。

## 3. 基本原则

### 3.1 风格定位

- 风格是“工程化、克制、规整、直角、低装饰”。
- 不追求卡片化、圆角化、营销化。
- 页面以可扫读、可维护、可复用为第一目标。

### 3.2 统一视觉语言

- 主内容背景为浅灰背景上的白色平面区域。
- 控件、按钮、分页、标签、表格、抽屉、详情表统一使用直角。
- 列表、抽屉、详情区优先使用细边框，不依赖阴影表达层级。
- 颜色只表达语义，不表达装饰。

### 3.3 统一工程语言

- 优先复用 `Bz*` 组件、`Admin*` 通用组件和现有样式类。
- 能在公共组件或公共样式层解决的问题，禁止在页面局部再造一套。
- 页面只描述业务数据、列定义、权限、操作，不重新定义基础 UI 规则。

## 5. 禁止项

以下规则为硬约束：

- 禁止在后台主体区域使用圆角按钮、圆角输入框、圆角分页、圆角标签。
- 禁止在同一页面混用多套复选框样式。
- 禁止在抽屉内部再嵌套纵向滚动表格。
- 禁止因为加载、翻页、展开筛选、进入批量模式导致列表或分页跳动。
- 禁止为了“避免抖动”在列表或抽屉表格内部预留左右滚动条 gutter 空白。
- 禁止分页当前页因为 `font-weight` 或 padding 变化导致尺寸变化。
- 禁止抽屉头部放置右上角关闭按钮。
- 禁止同一分组同时出现两处重复统计文案。
- 禁止页面自己决定例外实现；确需例外必须先更新本文档。

## 6. 页面壳层与列表页总体结构

标准后台列表页结构如下：

```text
页面内容区
┌────────────────────────────────────────────┐
│ 查询区，可展开/收起，可选                     │
├────────────────────────────────────────────┤
│ 工具栏：左侧业务按钮，右侧查询工具              │
├────────────────────────────────────────────┤
│ 表格主体                                     │
├────────────────────────────────────────────┤
│ 分页区 / 统计区                               │
└────────────────────────────────────────────┘
```

要求：

- 查询区、工具栏、表格、分页必须属于同一个连续区域。
- 这个连续区域通常放在一个 `BzCard` 内，但卡片 body 本身不需要额外内边距包裹表格区。
- 列表容器外层不再拆成多个割裂的大卡片。
- 工具栏和分页区背景色可与表格正文略有层次差，但仍属于同一区域。

## 7. 查询区规范

### 7.1 布局

- 查询区位于列表容器顶部。
- 默认折叠，由 `AdminTableTools` 控制开关。
- 查询区展开后使用白色背景和底部分隔线。
- 查询字段使用网格布局，不自由流排布。

### 7.2 交互

- 查询区按钮顺序固定为：`重置`、`搜索`。
- 输入框支持回车触发查询。
- 查询条件变化后点击搜索，分页列表回到第 `1` 页。
- 重置必须清空筛选条件并回到第 `1` 页。

### 7.3 文案

- 搜索框 placeholder 必须写清范围。
- `/admin/users` 使用：`按账号或昵称搜索`
- `/admin/roles` 使用：`搜索角色编码/名称`

## 8. 工具栏规范

### 8.1 布局

- 工具栏高度稳定，基线 `50px`。
- 左侧是业务按钮区。
- 右侧是查询工具区。
- 背景使用浅灰柔和背景。
- 底部有 `1px` 分隔线。

### 8.2 业务按钮区

- 高优先级主操作使用 `admin-toolbar-primary`。
- 低频或次级操作使用普通 `BzButton`。
- 不在工具栏重复渲染“页面标题”。

### 8.3 查询工具区

- 只承载搜索开关、刷新等查询辅助能力。
- 默认通过 `AdminTableTools` 提供。
- 查询工具区必须始终靠右。

## 9. 列表表格规范

后台列表有两种标准形态：

- 标准数据表：基于 `BzTable`
- 表格化 grid 列表：基于 `admin-grid-table`

### 9.1 标准数据表 `BzTable`

适用场景：

- `/admin/users` 主列表
- `/admin/roles` 主列表

强制要求：

- 表头、单元格、分页、滚动位置必须稳定。
- 水平溢出时允许横向滚动。
- 只允许横向滚动，不允许表格内部竖向滚动。
- 不预留左右滚动条 gutter。
- 表格高度随数据条数自然增长。
- 页面高度不足时，由外层页面或抽屉 body 提供纵向滚动。

### 9.2 grid 表格 `admin-grid-table`

适用场景：

- 抽屉中的关联对象选择表格
- 权限树表格
- 需要自定义行结构但仍保持表格观感的场景

标准结构：

```text
.admin-grid-table
  .admin-grid-table__viewport
    .admin-grid-table__row.admin-grid-table__row--head
      .admin-grid-table__cell
    .admin-grid-table__body
      .admin-grid-table__row
        .admin-grid-table__cell
  .admin-grid-table__footer，可选
```

强制要求：

- 最外层必须有完整外边框。
- 内部分隔线由行或单元格规则统一承担，不能与外边框叠出双倍粗线。
- 表格内容区与分页 footer 交界处必须有明确边界。
- footer 背景色必须与表格正文一致，而不是跟随外层卡片背景。
- 表格主体不允许内部纵向滚动。
- 表格主体不预留滚动条位置。
- 翻页加载时必须保持原列表高度稳定，不能先清空再加载。

### 9.3 边框规则

通用处理原则：

- 最外圈边框由表格容器负责。
- 行与行之间的横向分隔线由统一规则负责。
- 最后一行不能缺底边。
- 外边框不能和内部分隔线叠成 `2px` 粗线。

推荐落地方式：

- 使用统一容器边框。
- 内容行统一有底部分隔线。
- 与 footer 相接时，footer 自己承担左右下边框，避免上边框叠加。

### 9.4 选择列规则

- 选择列固定在第 `1` 列。
- 宽度稳定，基线 `44px ~ 48px`。
- 即使当前不显示勾选，也必须预留列位置时，需要明确说明；否则不要临时改列宽。
- 当前页部分选中时，表头复选框必须显示半选态。

## 10. 节点复选框规范

后台“节点型勾选”统一使用同一套原生 checkbox 样式。

统一类名：

- `admin-node-checkbox`

强制要求：

- 尺寸固定为 `14px * 14px`
- `margin: 0`
- 使用主色 `accent-color`
- `/admin/users` 抽屉中的角色分配列表，必须与 `/admin/roles` 抽屉中的权限节点勾选风格完全一致。

禁止：

- 一个页面内表头复选框是原生样式，行内勾选是 `BzCheckbox` 另一套视觉。
- 不同页面的节点勾选尺寸不一致。

## 11. 分页规范

### 11.1 组件

- 分页统一使用 `BzPagination`。

### 11.2 尺寸稳定

- 当前页和非当前页按钮尺寸必须一致。
- 当前页不得通过增大字重改变按钮宽度。
- 页码切换时不允许分页按钮整体重新排布。
- 页码按钮基线高度固定为 `30px`。

### 11.3 布局稳定

- 翻页时分页区位置不得跳动。
- 翻页 loading 只能覆盖列表内容，不得把列表替换成更矮的空态块。
- 总数说明在左，分页控件在右。
- 分页区本身应与表格主体视觉相连。

### 11.4 页码切换加载规则

- 若列表已有上一页数据，翻页时继续保留旧数据。
- 在旧数据上方显示局部 loading 遮罩。
- 只有首次进入且还没有任何数据时，才显示“加载中...”空态。

## 12. 抽屉规范 `AdminEntityDrawer`

### 12.1 头部

- 头部标题在竖直方向必须居中。
- 头部只保留标题，不显示右上角关闭按钮。
- 抽屉关闭通过以下路径完成：
  - 遮罩点击
  - footer 按钮

### 12.2 面板

- 抽屉默认从右侧滑出。
- 面板高为 `100vh`。
- body 独立滚动。
- footer 固定在底部。
- body 使用白色背景，外层允许浅灰页面氛围背景。

### 12.3 滚动规则

- 抽屉 body 负责纵向滚动。
- 抽屉内部的表格、权限树、关联列表都不再自己开启纵向滚动。
- 抽屉内部表格不预留左右滚动条位置。
- 超过视口高度时，由抽屉 body 统一滚动整页内容。

### 12.4 footer

- 只读态按钮：`关闭`
- 可编辑态按钮：`取消 + 保存`
- 二阶段确认态按钮：`返回 + 确认保存`

## 13. 抽屉内分组规范

抽屉内容采用纵向分组结构：

```text
标题
分组 A
分组 B
分组 C
footer
```

规则：

- 分组之间标准间距 `16px`
- 分组标题使用左侧 `3px` 主色竖线
- 分组标题区垂直居中
- 标题右侧允许放 1 个统计区或轻提示区
- 同一分组不得同时在顶部和底部重复展示同一统计文案

标准类：

- `role-manage-section`
- `role-manage-section__head`
- `role-manage-section__title`
- `role-manage-section__stat`
- `role-manage-section__hint`

## 14. 详情信息表规范

详情、新增、编辑中的基础信息区统一使用“详情表格”，而不是散列表单卡片。

标准结构：

```text
分组标题
┌──────┬──────────┬──────┬──────────┬──────┬──────────┐
│ 字段 │ 值/控件   │ 字段 │ 值/控件   │ 字段 │ 值/控件   │
└──────┴──────────┴──────┴──────────┴──────┴──────────┘
```

强制要求：

- 外层有完整边框。
- 标签列为浅灰背景。
- 值列为白色背景。
- 单元格高度稳定，基线 `40px`。
- 标签列宽固定，当前基线约 `112px`。
- 可编辑时，输入控件嵌入值单元格，不单独脱离表格。
- 必填星号使用统一红色规则，放在字段名后。

## 15. `/admin/users` 页面标准蓝图

本节定义的是“必须实现成什么样”，不是“可选示例”。

### 15.1 列表页结构

页面顺序：

1. 可收起查询区
2. 工具栏
3. 用户主列表
4. 分页区
5. 浮层：重置密码弹窗、用户管理抽屉

### 15.2 查询区

字段固定为：

- 账号
- 状态

交互：

- 账号支持按账号或昵称搜索
- 状态支持全部/启用/停用

### 15.3 工具栏

默认业务按钮：

- 新增
- 批量停用
- 批量重置密码
- 批量删除

右侧查询工具：

- 搜索区开关
- 刷新

### 15.4 主列表列定义

列顺序固定为：

1. 选择列，批量模式下显示
2. 账号，左侧冻结
3. 昵称
4. 类型
5. 状态
6. 创建人
7. 创建时间
8. 更新人
9. 更新时间
10. 操作，右侧冻结

规则：

- 账号列是主要识别列。
- 类型、状态使用 `BzTag`。
- 时间统一 `YYYY-MM-DD HH:mm:ss`。
- 技术型字段使用等宽字体。
- 行操作顺序固定：`详情`、`维护`、`启用/停用`、`重置密码`、`删除`

### 15.5 批量模式

点击任一批量操作后进入二阶段批量模式：

- 工具栏替换为批量模式条
- 文案格式：`批量停用中，已选 X 项`
- 右侧按钮：`确认`、`取消`
- 表格显示选择列与全选框

### 15.6 删除与危险操作

- 删除单个用户必须二次确认。
- 批量删除必须二次确认。
- 批量重置密码必须二次确认。

### 15.7 用户抽屉

标题按模式切换：

- `新增用户`
- `用户详情`
- `编辑用户`

宽度基线：

- `1180px`

分组顺序：

1. 用户信息
2. 角色分配，仅内部用户且有权限时显示

### 15.8 用户信息分组

字段结构：

- 新增态：用户名、用户类型、昵称、初始密码、状态、角色概览
- 详情/编辑态：用户名、用户类型、昵称、状态、创建人、创建时间、更新人、更新时间、角色概览

规则：

- 新增态用户名、初始密码、昵称为必填
- 用户类型在本页只读显示
- 角色概览显示 `已选 X 项`

### 15.9 角色分配分组

结构固定为：

1. 分组标题：`角色分配`
2. 右侧统计：`已选 X / Y 项`
3. 分组内搜索工具条
4. 关联分页表格
5. 分页 footer

搜索工具条：

- 搜索框 placeholder：`搜索角色编码/名称`
- 右侧按钮：`重置`、`搜索`

角色分配表格要求：

- 使用 `admin-grid-table`
- 表头固定三列：选择列、角色编码、角色名称
- 表格外层必须有边框
- 分页区必须与表格视觉一体
- 表格内部不出现纵向滚动条
- 翻页 loading 不得让分页条跳动

### 15.10 保护账号规则

下列账号视为保护账号：

- `SYSTEM` 用户
- `INTERNAL` 且账号名为 `admin`

UI 规则：

- 主列表批量选择时，这些行禁选
- 行内维护/停用/重置密码可按业务规则禁用
- 不隐藏行，只禁用对应操作

## 16. `/admin/roles` 页面标准蓝图

### 16.1 列表页结构

页面顺序：

1. 可收起查询区
2. 工具栏
3. 角色主列表
4. 分页区
5. 浮层：角色权限抽屉

### 16.2 查询区

字段固定为：

- 角色
- 状态

角色搜索 placeholder 固定为：

- `搜索角色编码/名称`

### 16.3 工具栏

业务按钮：

- 新增

查询工具：

- 搜索区开关
- 刷新

### 16.4 主列表列定义

列顺序固定为：

1. 编码，左侧冻结
2. 名称
3. 状态
4. 创建人
5. 创建时间
6. 更新人
7. 更新时间
8. 操作，右侧冻结

行操作顺序固定为：

- 详情
- 编辑
- 删除

### 16.5 角色抽屉

标题按模式切换：

- `新增角色`
- `角色详情`
- `编辑角色`
- 权限变更确认阶段标题：`确认权限变更`

宽度基线：

- `1180px`

分组顺序：

1. 角色信息
2. 权限内容，仅有权限时显示
3. 确认权限变更，仅二阶段确认时显示

### 16.6 角色信息分组

字段结构：

- 编码
- 名称
- 状态
- 创建人
- 创建时间
- 更新人
- 更新时间
- 权限概览
- 资源总数

规则：

- 新增或可编辑态，编码/名称/状态按权限切换为可编辑控件
- 只读态使用详情表格展示
- 权限概览显示 `已选 X / Y 项`

### 16.7 权限内容分组

结构固定为：

1. 分组标题：`权限内容`
2. 右侧唯一统计：`已选 X / Y 项`
3. 搜索与操作工具条
4. 权限树表格

禁止：

- 分组底部再放一条“当前筛选结果 X 项，共 Y 项资源”
- footer 重复显示与标题右侧相同的已选统计

搜索与操作工具条：

- 搜索框 placeholder：`搜索资源名称/编码/类型`
- 操作按钮：`全部展开`、`全部收起`
- 编辑态额外提供：`清空选择`

### 16.8 权限树表格

必须使用 `admin-grid-table` + 权限树业务样式。

表头固定六列：

1. 选择列
2. 资源名称
3. 类型
4. 资源编码
5. 状态
6. 按钮权限

树节点规则：

- 缩进步长固定：`22px`
- 展开按钮尺寸 `14px * 14px`
- 节点勾选使用 `admin-node-checkbox`
- 按钮权限在最后一列以 checkbox chip 形式展示
- 树表不分页
- 树表不出现内部纵向滚动条
- 数据多时由抽屉 body 统一滚动

状态与类型规则：

- 目录、菜单、功能、按钮使用不同浅色标签
- 停用状态使用危险语义颜色

### 16.9 权限变更确认态

确认阶段单独展示一个分组：

- 标题：`确认权限变更`
- 标题下提示文案：说明绿色描边和红色删除线语义
- 右侧统计显示 diff 摘要
- 主体仍使用同一套权限树表格

差异规则：

- 新增权限：绿色描边
- 移除权限：红色删除线
- 未变化节点仅用于展示路径

### 16.10 角色删除

- 删除角色必须二次确认。
- 确认文案中展示角色名称与编码。

## 17. 加载、空态、错误规范

### 17.1 列表页加载

- 列表页加载由列表区域承担。
- 不允许整页闪烁。

### 17.2 抽屉中的关联表格加载

- 关联表格已有数据时，翻页、搜索、重载都必须保留旧数据。
- loading 以遮罩叠加在表格上。
- 不允许先切换成更矮的“加载中”空态。

### 17.3 空态

- 主列表默认空态：`暂无数据`
- 角色分配空态：`暂无角色`
- 权限树空态：`暂无可授权资源`

### 17.4 错误提示

- 抽屉表单错误优先显示在分组内顶部 `BzAlert`
- 不只依赖全局 message

## 18. 响应式规则

- 移动端下工具栏、分组标题区、footer 操作区可纵向堆叠。
- 详情表在窄屏下可切成 block 结构逐行展示。
- 权限树或宽表在窄屏下允许横向滚动。
- 即使移动端允许横向滚动，也不允许内部纵向滚动替代抽屉整体滚动。

## 19. 实现检查清单

实现任一后台管理页前，必须逐条自检：

- 是否优先复用了 `BzTable` 或 `admin-grid-table`
- 是否使用 `AdminTableTools` 控制查询区开关
- 查询区、工具栏、表格、分页是否属于同一个连续区域
- 是否全部使用直角控件
- 是否没有使用右上角抽屉关闭按钮
- 抽屉内部是否只有 body 提供纵向滚动
- 表格内部是否没有纵向滚动条
- 是否没有预留左右滚动条 gutter
- 分页切换时是否保留旧数据并使用遮罩 loading
- 当前页与非当前页分页按钮是否尺寸一致
- 节点型勾选是否统一使用 `admin-node-checkbox`
- grid 表格是否具有完整外边框
- grid 表格 footer 是否与表格主体同背景、同边框体系
- 统计文案是否只有一处，不重复
- 危险操作是否都有二次确认
- 权限不足的操作是否隐藏，而不是禁用

## 20. 最终原则

若 AI 根据本文档实现 `/admin/users` 或 `/admin/roles`，最终输出必须默认满足以下结果：

- 不需要再补充“把抽屉头部居中”“去掉关闭按钮”“去掉内部滚动条”“统一分页按钮”“统一 checkbox”“补表格边框”“修分页闪烁”这类返工指令。

换句话说，本文档描述的不是“方向”，而是“验收标准”。
