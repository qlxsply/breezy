# web-admin 管理后台 UI 设计规范

## 1. 文档目的

本规范用于统一 `web-admin` 管理后台项目的视觉风格、页面结构、交互语言、组件使用方式与后续页面设计标准。

本规范的目标：

- 保证新增页面与现有后台风格一致。
- 保证同类页面、同类操作、同类状态具有一致的视觉表达。
- 降低页面实现中的随意性，避免重复造轮子与风格漂移。
- 为后续功能开发、重构、联调和代码审查提供统一依据。

本规范适用于：

- `web-admin` 下所有后台页面。
- 所有后台抽屉、弹窗、表格、查询区、详情区、操作区。
- 基于 `Bz*` 组件体系实现的新页面与既有页面优化。

## 2. 设计原则

### 2.1 总体风格

- 风格定位为“专业、克制、轻量、清晰”。
- 避免过强装饰、过重阴影、过多颜色、过密信息堆叠。
- 优先强调信息层级、可扫读性和高频操作效率。
- 页面应体现工具型后台的稳定感，而不是营销型页面的情绪化表达。

### 2.2 视觉原则

- 主体区域以浅色背景、白色卡片、浅灰边框为主。
- 强调分区、留白、对齐，而不是依赖大量色块划分内容。
- 所有强调信息优先使用主色、文字粗细、边框和背景微差表达。
- 状态色只用于表达状态，不用于装饰。

### 2.3 交互原则

- 用户应能快速判断“页面是什么”“当前能做什么”“下一步怎么做”。
- 同类操作必须使用一致的文案、位置与反馈方式。
- 危险操作必须明显区分，并保持二次确认。
- 非可用操作优先展示为禁用态，而不是直接消失，除非该操作在当前语义下根本不存在。

### 2.4 工程原则

- 优先复用已有 `Bz*` 组件和后台通用布局。
- 优先复用已有样式类与现成页面模式。
- 新设计应能落到现有组件体系，不引入额外 UI 框架。
- 页面实现必须兼顾桌面端与移动端可用性。

## 3. 现有设计基线

当前后台 UI 的主要设计基线来自以下文件：

- `src/styles/theme.css`
- `src/styles/admin-page.css`
- `src/app/admin-shell.css`
- `src/components/bz/bz-react.css`

这些文件是现阶段的视觉实现基础。本规范用于约束后续新增与调整，不要求立即一次性重构所有历史页面，但后续修改应尽量向本规范收敛。

## 4. 主题与设计令牌

### 4.1 主色

- 主色：`#3B82F6`
- 主色深色态：`#2563EB`
- 主色浅背景：`#EFF6FF`
- 主色边框：`#BFDBFE`

主色用途：

- 主按钮
- 当前激活项
- 可点击高亮态
- 重点操作强调
- 聚焦边框与聚焦阴影

### 4.2 背景色

- 页面背景：`#F8FAFC` 到 `#F1F5F9` 的浅渐变或浅底
- 卡片背景：`#FFFFFF`
- 柔和背景：`#F8FAFC`
- 轻高亮背景：`#EFF6FF`

要求：

- 页面主背景要轻，不应压过内容本身。
- 卡片与页面背景必须有可识别层次，但不应反差过强。

### 4.3 文字色

- 主文字：`#0F172A` 或 `#1E293B`
- 次级文字：`#475569`
- 辅助文字：`#64748B`
- 弱化文字：`#94A3B8`

要求：

- 页面标题、分组标题使用主文字。
- 字段值、普通正文使用主文字或次级文字。
- 说明文、提示文、计数说明使用辅助文字。
- 禁用态和弱提示使用弱化文字。

### 4.4 边框与分隔

- 主边框：`#E2E8F0`
- 次边框：`#DBE1EA` 或 `#DCE6F2`

要求：

- 卡片、抽屉面板、表格容器、输入框统一采用浅边框。
- 分隔线应轻量，不能形成过强割裂。

### 4.5 状态色

| 语义 | 建议颜色 | 用途 |
| --- | --- | --- |
| 成功/启用 | `#15803D` / `#10B981` | 启用、成功、正常 |
| 失败/危险 | `#B91C1C` / `#DC2626` | 删除、停用、失败 |
| 警告 | `#C2410C` / `#F59E0B` | 警示、暂停、需关注 |
| 信息 | `#2563EB` | 编辑、详情、可跳转 |

要求：

- 删除类操作始终使用红色语义。
- 编辑类操作始终使用蓝色语义。
- 启用类操作始终使用绿色语义。
- 详情类操作应保持中性偏灰，不与编辑混淆。

## 5. 排版规范

### 5.1 字体

- 英文与数字优先使用 `Inter`、`Segoe UI`、系统无衬线字体。
- 中文优先使用 `PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 编码、路径、权限码等技术型字段使用等宽字体，如 `Consolas`、`Courier New`。

### 5.2 标题层级

- 页面级标题：16px 到 18px，700 字重。
- 分组标题：15px 到 16px，700 字重。
- 卡片次标题/区块名：14px，600 到 700 字重。
- 正文与字段值：13px 到 14px。
- 说明、提示、统计辅助文：12px 到 13px。

### 5.3 行高与可读性

- 普通文本行高建议 `1.5` 到 `1.6`。
- 表单字段、表格单元、标签行内文本应保持垂直居中。
- 禁止出现文本与开关、文本与按钮、文本与图标在 y 轴上明显不对齐的情况。

## 6. 间距规范

建议使用 4 的倍数作为基础节奏。

| 场景 | 建议值 |
| --- | --- |
| 微小间距 | 4px |
| 紧凑元素间距 | 8px |
| 常规元素间距 | 12px |
| 分组内字段间距 | 14px 到 16px |
| 卡片内边距 | 16px 到 20px |
| 分组之间留白 | 16px 到 24px |
| 页面区块之间留白 | 20px 到 24px |

要求：

- 分组内部间距要统一。
- 分组之间留白必须明显大于字段之间留白。
- 标题与正文之间应有明确间隔，不能贴在一起。

## 7. 圆角、阴影与质感

- 输入框、操作按钮：8px 左右圆角。
- 卡片、抽屉内分组面板：12px 到 16px 圆角。
- 阴影应轻量，只用于抽屉、浮层、悬浮面板。
- 常规表单区、页面卡片优先使用边框，不依赖重阴影。

要求：

- 不允许同时叠加重阴影、深渐变、强边框，避免视觉负担。

## 8. 页面整体结构

### 8.1 标准后台页面结构

后台页面默认遵循：

1. 页面容器
2. 查询区或工具区
3. 主表格/主内容卡片
4. 分页区
5. 弹窗/抽屉等浮层

### 8.2 页面头部

- 页面标题位于主卡片头部左侧。
- 工具按钮位于右侧。
- 头部应优先承载操作，不应堆叠过多说明文字。

### 8.3 查询区

- 查询区默认可收起。
- 查询区内字段必须成组排列，标签、输入控件、操作按钮对齐。
- 查询条件不宜过密，优先按 2 列到 4 列网格布局。
- 搜索、重置、展开/收起按钮顺序应统一。

### 8.4 主内容区

- 主内容区通常使用 `BzCard` 承载。
- 表格外层应具备清晰边框和圆角。
- 空状态、加载状态、分页状态必须有统一视觉规则。

## 9. 导航与壳层规范

### 9.1 侧边栏

- 侧边栏宽度应稳定，收起态和展开态切换平滑。
- 激活项使用主色边框、浅蓝背景和蓝色文字。
- 非激活项 hover 使用浅灰或浅蓝背景。
- 菜单层级通过缩进体现，不依赖过多装饰线。

### 9.2 顶部区域

- 顶部栏应保持轻量、扁平和低干扰。
- 仅放置导航辅助、系统入口、用户信息、必要工具按钮。

## 10. 表格设计规范

### 10.1 表格基础

- 表头背景应与正文略有区分，但不应过重。
- 行 hover 允许有轻微背景变化。
- 表格单元格优先保持单行省略，详细信息通过 tooltip、详情抽屉或详情页展开。

### 10.2 列内容规则

- 名称类字段左对齐。
- 编码、路径、权限码、组件路径优先使用等宽字体。
- 布尔值优先明确显示“是/否”“启用/停用”。
- 状态类字段要有稳定颜色语义。

### 10.3 树形表格

- 展开/收起按钮使用统一 SVG 图标。
- 缩进只表达层级，不应挤压主要文本可读空间。
- 叶子节点与父节点图标尺寸和位置应一致。

## 11. 操作按钮规范

### 11.1 操作按钮顺序

默认推荐顺序：

1. 详情
2. 编辑/维护
3. 启用/停用
4. 重置/复制/其他常规操作
5. 删除

要求：

- 危险操作尽量靠后。
- 同一页面同类表格必须保持相同操作顺序。

### 11.2 操作按钮数量约定

- 当行操作按钮数量小于等于 3 时，全部直出。
- 当行操作按钮数量大于 3 时，仅保留前 2 个直出。
- 第 3 个及其后续操作统一收进 `更多`。
- 该规则由 `AdminActionBar` 统一承载，页面不得各自实现不同逻辑。

### 11.3 禁用态规则

- 不可操作但业务上“存在”的按钮应优先显示为禁用态。
- 禁用态按钮必须具有明确的灰化视觉表现。
- 禁用态不得与隐藏态混用造成理解歧义。

适合禁用显示的场景：

- 该资源类型不存在下级创建能力。
- 系统内置对象不允许删除。
- 当前权限不足但页面希望保留完整能力视图。

### 11.4 危险操作

- 删除、强制下线、重置敏感信息等操作必须二次确认。
- 删除按钮颜色保持红色语义，不能与普通按钮同色。

## 12. 表单设计规范

### 12.1 基本规则

- 后台表单统一使用 `BzForm`、`BzFormItem` 和 `Bz*` 输入组件。
- 表单项优先按两列或单列网格排列。
- 字段标签与控件之间要保持稳定间距。
- 必填项必须明确标注。

### 12.2 字段对齐

- 同一区域内输入框、下拉框、开关、标签文字必须高度协调。
- 开关类控件所在行，标签文字与开关必须在 y 轴居中对齐。
- 禁止出现同一行多个控件高度明显不一致的情况。

### 12.3 只读字段

- 只读字段优先使用禁用但可阅读的输入组件，或使用明确的“属性名 - 属性值”形式展示。
- 只读态不能看起来像报错态。

### 12.4 错误反馈

- 表单校验错误应在表单区内明确展示。
- 错误信息用红色表达，但不要造成整个页面强烈闪烁感。

## 13. 抽屉与弹窗规范

### 13.1 选择规则

- 列表行维护、配置编辑、较复杂表单优先使用抽屉。
- 简短确认、简单录入、轻量配置可以使用弹窗。
- 内容较多、需要滚动或多分组展示时，必须优先使用抽屉。

### 13.2 抽屉标题

- 抽屉顶部只展示动作标题。
- 标题示例：`编辑资源`、`用户维护`、`角色权限分配`、`详情`。
- 不在标题区拼接用户名、编码、路径、资源标识等业务数据。

### 13.3 抽屉内容布局

- 抽屉内容必须按业务语义分组。
- 推荐分组示例：
  - 基础信息
  - 路由信息
  - 状态配置
  - 权限绑定
  - 角色分配
  - 高级配置
- 每个分组必须有独立承载区域，如卡片或浅边框区块。
- 分组标题与字段内容之间要有明确间距。
- 分组之间要有明显留白。

### 13.4 详情与编辑关系

- 详情与编辑页面应尽量共用结构布局。
- 详情态与编辑态的核心差别在于交互能力，不在于整体视觉完全不同。
- 详情页中的特定业务分组只在相关资源类型下出现。

示例：

- 按钮资源才显示“权限码绑定”。
- 非按钮资源不应渲染“权限码绑定”区域占位。

### 13.5 抽屉 footer

- 无编辑能力时，底部按钮使用 `关闭`。
- 可编辑时，底部按钮使用 `取消 + 保存`。
- 确认型二阶段流程允许使用 `返回 + 确认`。

## 14. 详情页与只读展示规范

### 14.1 展示风格

- 详情内容允许使用表单只读组件，也允许使用详情字段卡片。
- 重点是规整、稳定、可扫读，而不是全部使用输入框伪装。

### 14.2 字段组织

- 用户标识、资源标识、系统属性等应归入基础信息组。
- 业务行为配置应归入独立分组。
- 列表型只读信息，如权限码、角色列表、按钮列表，可直接用列表展示，不强制包裹重边框容器。

## 15. 权限、角色、资源类页面规范

### 15.1 层级信息

- 目录、菜单、功能、按钮等层级关系必须通过缩进、标签、树节点结构明确表达。
- 权限码、路径、组件路径等技术字段应保持紧凑且易区分。

### 15.2 按钮权限展示

- 如果后端语义是“功能授权”，按钮列表只是权限标识展示，则文案必须明确说明。
- 不得用界面暗示不存在的独立授权能力。

### 15.3 资源管理

- `新增子项` 这类与资源类型相关的操作，在业务上存在但当前行不可执行时，应显示禁用态。
- 资源树的展开/收起图标必须使用统一 SVG 图标组件。

## 16. 用户管理类页面规范

### 16.1 用户维护抽屉

- 标题使用动作名称，如 `用户维护`。
- 用户名、用户类型等标识信息应放在基础信息组内。
- 昵称、状态等可编辑字段应放在维护配置组内。
- 角色分配属于独立业务分组，不应与基础表单混在同一区块。

### 16.2 角色分配列表

- 支持搜索时，搜索框应位于分组头部下方。
- 已选数量可放在分组头部右侧。
- 角色列表项选中态要有清晰但不过度的高亮反馈。

## 17. 查询、筛选与搜索规范

- 搜索框提示词应说明搜索范围，如“搜索角色编码/名称”。
- 筛选项命名应业务清晰，不使用含混词汇。
- 筛选区必须提供 `搜索` 与 `重置`。
- 高级筛选收起/展开文案应统一。

## 18. 空状态、加载与反馈规范

### 18.1 空状态

- 空状态文案应简洁，如“暂无数据”“暂无角色”“暂无可授权资源”。
- 仅在必要时补充说明，不堆叠过多描述。

### 18.2 加载状态

- 表格、抽屉主体、角色列表等局部区域应支持局部 loading。
- loading 不应阻断整个页面，除非确实是全局加载。

### 18.3 反馈方式

- 成功操作使用轻量 message。
- 危险操作失败或关键校验失败使用明确错误提示。
- 抽屉内表单错误优先在抽屉内可见，不依赖全局 message 单独承载。

## 19. 响应式规范

### 19.1 桌面端

- 优先保证 1280 宽度及以上有舒适布局。
- 复杂抽屉可使用 860px、960px、1120px 等分档宽度。

### 19.2 平板端

- 分组内两列表单应允许收敛到单列。
- 操作区、footer、查询区要避免横向拥挤。

### 19.3 手机端

- 抽屉应允许接近全屏宽度。
- 工具栏、footer 操作按钮允许纵向堆叠。
- 标签、路径、编码等长文本必须可换行或省略。

## 20. 图标规范

- 图标优先使用现有 `Bz*` 图标组件或内联 SVG。
- 同类行为图标应统一，不允许同项目中多套相同语义图标并存。
- 树形展开/收起、侧边导航折叠、搜索、刷新等高频图标应做成可复用组件。

## 21. 组件复用规范

优先复用：

- `AdminEntityDrawer`
- `AdminActionBar`
- `AdminTableTools`
- `BzButton`
- `BzInput`
- `BzSelect`
- `BzTable`
- `BzPagination`
- `BzSwitch`
- `BzCheckbox`
- `BzTag`
- `BzLoading`

要求：

- 禁止页面内重复发明新风格按钮、新风格抽屉、新风格表格交互。
- 新增能力优先扩展通用组件，而不是在单页硬写一套特殊实现。

## 22. 文案规范

- 动作标题简洁直接，如“新增资源”“编辑资源”“用户维护”。
- 操作文案统一使用动词，如“详情”“编辑”“删除”“新增子项”“关闭”“保存”。
- 空状态、提示文案避免口语化和情绪化。
- 不在抽屉标题中拼接业务字段。

## 23. 页面实现建议

新增后台页面时，建议按以下顺序设计：

1. 明确页面类型：列表页、树页、详情页、维护页、配置页。
2. 先决定页面结构：查询区、工具区、主内容区、详情抽屉。
3. 再决定分组：基础信息、状态信息、业务配置、权限配置。
4. 复用通用操作条、抽屉、表单网格与状态样式。
5. 最后微调业务特有的字段顺序与信息密度。

## 24. 禁止事项

- 禁止在后台页面中引入不一致的 UI 框架。
- 禁止在标题区堆叠业务标识信息。
- 禁止在同一后台中出现多套不同操作按钮规则。
- 禁止大量使用无意义说明文字占据视觉空间。
- 禁止通过颜色滥用表达层级。
- 禁止把可禁用的操作直接随意隐藏。
- 禁止同类页面出现明显不同的表单、抽屉、详情布局模式。

## 25. 未来演进建议

后续如继续演进 `web-admin`，建议把本规范逐步沉淀为以下可复用资产：

- 通用页面模板
- 通用详情分组组件
- 通用后台表单网格组件
- 通用状态展示组件
- 通用树节点展开图标组件
- 通用禁用操作样式规范
- 通用抽屉标题与 footer 规范

## 26. 结论

`web-admin` 的 UI 不追求花哨，而追求：

- 页面清晰
- 分组明确
- 操作统一
- 信息可扫读
- 高密度但不混乱
- 可持续扩展

后续所有后台页面新增、调整、重构，都应以本规范为准，优先保持全局一致性，再考虑局部个性化实现。
