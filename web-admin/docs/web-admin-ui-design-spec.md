# web-admin 管理后台 UI 设计规范

## 1. 文档目的

本规范用于统一 `web-admin` 管理后台项目的视觉风格、页面结构、交互语言、组件使用方式与后续页面设计标准。

本规范的目标：

- 保证新增页面与现有后台风格一致。
- 保证同类页面、同类操作、同类状态具有一致的视觉表达。
- 降低页面实现中的随意性，避免重复造轮子与风格漂移。
- 为后续功能开发、重构、联调、代码评审、UI 走查和验收提供统一依据。
- 让规范可以直接落到 `web-admin` 现有组件、样式和页面模式，而不是停留在抽象设计层面。

## 2. 适用范围与执行要求

### 2.1 适用范围

本规范适用于：

- `web-admin` 下所有后台页面。
- 所有后台查询区、工具区、表格、分页、抽屉、弹窗、详情区、操作区。
- 基于 `Bz*` 组件体系实现的新页面与既有页面优化。
- 基于 `AdminActionBar`、`AdminEntityDrawer`、`AdminTableTools` 等通用后台组件实现的页面。

### 2.2 执行要求

- 新增页面必须遵循本规范。
- 既有页面在重构、功能调整或样式调整时，必须逐步向本规范收敛。
- 能通过扩展通用组件解决的问题，必须优先扩展通用组件，不允许在单页硬编码一套特殊实现。
- 页面开发、代码评审、UI 走查和验收时，均以本规范作为判断依据。
- 本规范未明确说明的细节，优先参考项目现有通用组件与样式基线，而不是由页面开发者自行决定。

### 2.3 例外登记机制

- 所有页面默认必须遵循本规范，不存在“开发者自行决定例外”的空间。
- 确有业务特殊性的页面，必须先判断是否能通过扩展 `Bz*` 组件、`AdminActionBar`、`AdminEntityDrawer`、`AdminTableTools` 或统一样式层解决。
- 只有无法通过通用能力解决时，才允许登记例外。
- 例外必须登记在本规范文档或与本规范同级的专项补充文档中，不允许只存在于口头说明、PR 描述或单页注释中。

例外登记至少包含以下信息：

| 页面/组件 | 特殊场景 | 例外原因 | 影响范围 | 是否需后续收敛 |
| --- | --- | --- | --- | --- |
| 示例：角色授权对比抽屉 | 需要双栏差异对比 | 通用抽屉暂不支持对比型布局 | 仅角色授权页面 | 是 |

## 3. 设计原则

### 3.1 总体风格

- 风格定位为“专业、克制、轻量、清晰”。
- 避免过强装饰、过重阴影、过多颜色、过密信息堆叠。
- 优先强调信息层级、可扫读性和高频操作效率。
- 页面应体现工具型后台的稳定感，而不是营销型页面的情绪化表达。

### 3.2 视觉原则

- 主体区域以浅色背景、白色卡片、浅灰边框为主。
- 强调分区、留白、对齐，而不是依赖大量色块划分内容。
- 所有强调信息优先使用主色、文字粗细、边框和背景微差表达。
- 状态色只用于表达状态，不用于装饰。

### 3.3 交互原则

- 用户应能快速判断“页面是什么”“当前能做什么”“下一步怎么做”。
- 同类操作必须使用一致的文案、位置与反馈方式。
- 危险操作必须明显区分，并保持二次确认。
- 因业务状态、数据属性或系统规则导致暂不可用的操作，优先展示为禁用态。
- 因当前用户或角色无权限导致不可用的操作，必须隐藏，不得以禁用态展示。

### 3.4 工程原则

- 优先复用已有 `Bz*` 组件和后台通用布局。
- 优先复用已有样式类与现成页面模式。
- 新设计必须落到现有组件体系，不引入额外 UI 框架。
- 页面实现必须兼顾桌面端与移动端可用性。
- 页面内不得随意硬编码基础颜色、基础阴影、基础圆角、基础间距和基础状态样式。

## 4. 现有项目设计基线

### 4.1 样式与布局基线

当前后台 UI 的主要设计基线来自以下文件：

- `src/styles/theme.css`
- `src/styles/admin-page.css`
- `src/app/admin-shell.css`
- `src/components/bz/bz-react.css`

这些文件是现阶段视觉实现基础。本规范用于约束后续新增与调整，不要求立即一次性重构所有历史页面，但后续修改必须尽量向本规范收敛。

### 4.2 组件基线

当前后台页面应优先基于以下组件落地：

- `BzButton`
- `BzCard`
- `BzForm`
- `BzFormItem`
- `BzInput`
- `BzSelect`
- `BzSwitch`
- `BzCheckbox`
- `BzTable`
- `BzPagination`
- `BzTag`
- `BzTooltip`
- `BzOverflowTooltip`
- `BzLoading`
- `BzEmpty`
- `BzAlert`
- `BzDialog`
- `AdminActionBar`
- `AdminDetailTable`
- `AdminEntityDrawer`
- `AdminTableTools`

### 4.3 页面模式基线

当前项目已经沉淀出以下后台页面模式：

- `AdminShell` 负责侧边栏、顶部栏、标签栏和内容视口。
- 列表页通常由查询区、主表格卡片、分页区和维护浮层组成。
- 查询区默认可由 `AdminTableTools` 控制显示与隐藏。
- 列表操作列默认通过 `AdminActionBar` 承载。
- 复杂维护优先使用 `AdminEntityDrawer`。
- 简短录入或确认优先使用 `BzDialog`。

## 5. 主题与设计令牌

### 5.1 令牌使用原则

- 优先使用 `theme.css` 中已有 CSS 变量和统一语义颜色。
- 页面内不得随意硬编码主色、边框色、背景色、文字色、阴影、圆角和间距。
- 当现有设计令牌不足时，应优先扩展 `theme.css` 或统一样式层，再由页面消费。
- 页面级样式可以处理局部业务布局，但不允许通过 `style jsx`、局部 CSS 或内联样式重新定义一套基础视觉体系。
- 同类组件的 `hover`、`active`、`focus`、`disabled` 状态必须使用统一令牌或统一语义值。

### 5.3 间距、圆角、阴影令牌基线

- 间距节奏使用 4 的倍数，优先落在 `4px`、`8px`、`12px`、`16px`、`20px`、`24px`。
- 按钮、输入框、分页按钮默认圆角为 `8px`。
- 卡片默认圆角基线为 `10px` 到 `14px`。
- 抽屉内分组面板常用圆角基线为 `16px`。
- 常规内容卡片优先使用浅边框和轻阴影，不依赖重阴影表达层级。
- 当前常用阴影基线：
  - 卡片轻阴影：`0 4px 12px rgba(15, 23, 42, 0.05)`
  - 浮层/下拉：`0 8px 24px rgba(15, 23, 42, 0.12)`
  - 弹窗：`0 20px 40px rgba(15, 23, 42, 0.24)`
  - 抽屉：`-16px 0 40px rgba(15, 23, 42, 0.18)`

### 5.4 z-index 分层基线

当前项目已有分层基线如下，后续新增浮层必须沿用该层级体系：

| 层级对象 | 当前基线 |
| --- | --- |
| 侧边栏 | `220` |
| 固定顶部壳层 | `200` |
| 页面内局部辅助元素 | `40` 及以下 |
| 页面级抽屉 `AdminEntityDrawer` | `500` |
| 弹窗 `BzDialog` | `1700` |
| 全局 message | `2000` |
| 下拉菜单 | `2200` |
| 溢出 tooltip | `4000` |

后续新增层级时必须遵守：

- 不允许在单页随意使用极大 `z-index` 覆盖现有体系。
- 新增层级应尽量插入现有语义区间，而不是直接突破到更高层。

## 6. 排版规范

### 6.1 字体

- 英文与数字优先使用 `Inter`、`Segoe UI`、系统无衬线字体。
- 中文优先使用 `PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 编码、路径、组件路径、权限码等技术型字段使用等宽字体，如 `Consolas`、`Courier New`。

### 6.2 标题层级

- 页面级标题：`18px` 左右，700 字重。
- 查询区标题：`15px` 左右，700 字重，允许搭配主色短竖条。
- 分组标题：`15px` 到 `16px`，700 字重。
- 卡片次标题/区块名：`14px`，600 到 700 字重。
- 正文与字段值：`13px` 到 `14px`。
- 说明、提示、统计辅助文：`12px` 到 `13px`。

### 6.3 行高与可读性

- 普通文本行高建议 `1.5` 到 `1.6`。
- 表单字段、表格单元、标签行内文本应保持垂直居中。
- 禁止出现文本与开关、文本与按钮、文本与图标在 y 轴上明显不对齐的情况。

## 7. 间距规范

建议使用 4 的倍数作为基础节奏。

| 场景 | 建议值 |
| --- | --- |
| 微小间距 | `4px` |
| 紧凑元素间距 | `8px` |
| 常规元素间距 | `12px` |
| 分组内字段间距 | `14px` 到 `16px` |
| 卡片内边距 | `16px` 到 `20px` |
| 分组之间留白 | `16px` 到 `24px` |
| 页面区块之间留白 | `20px` 到 `24px` |

要求：

- 分组内部间距要统一。
- 分组之间留白必须明显大于字段之间留白。
- 标题与正文之间应有明确间隔，不能贴在一起。

## 8. 圆角、阴影与质感

- 输入框、操作按钮、分页按钮：`8px` 左右圆角。
- 卡片、抽屉内分组面板：`12px` 到 `16px` 圆角。
- 阴影应轻量，只用于抽屉、浮层、弹窗和悬浮面板。
- 常规表单区、页面卡片优先使用边框，不依赖重阴影。

要求：

- 不允许同时叠加重阴影、深渐变、强边框。
- 页面主要内容区优先保持干净平整，只让浮层承担明显悬浮感。

## 9. 页面整体结构

### 9.1 标准后台页面结构

后台页面默认遵循以下结构：

1. 页面容器
2. 管理列表主区域或主内容区
3. 分页区，若当前数据形态需要分页
4. 弹窗 / 抽屉等浮层

管理列表页默认采用“Excel 风格管理列表”结构：

```text
页面容器
┌────────────────────────────────────────────┐
│ 筛选条件，可收起，默认收起                  │
├────────────────────────────────────────────┤
│ 业务操作按钮区                  查询工具区  │
├────┬────────┬────────┬──────────────┬──────┤
│ 选 │ 列 A   │ 列 B   │ ...          │ 操作 │
├────┼────────┼────────┼──────────────┼──────┤
│    │ 数据行 │ 数据行 │ ...          │ 操作 │
└────┴────────┴────────┴──────────────┴──────┘
分页区，可选
```

要求：

- 筛选条件、工具栏、表格、分页应视觉上属于同一个列表区域，不再拆成多个割裂的大卡片。
- 顶部筛选条件默认收起，仅在用户打开搜索时显示。
- 列表区域应保持边框、表头、行高、分页和滚动条位置稳定，避免查询、翻页、批量模式切换时页面抖动。
- 树形列表、分页列表、可批量选择列表、只读列表都应优先复用同一套管理列表结构。

### 9.2 页面头部与壳层

- 页面整体运行在 `AdminShell` 下。
- 壳层结构遵循：侧边导航、顶部栏、标签栏和内容视口。
- 主内容区独立滚动，不依赖浏览器整页滚动。
- 侧边栏、顶部栏和标签栏不承载具体业务表单与业务说明。

### 9.3 查询区

- 查询区默认收起。
- 查询区打开后位于当前管理列表区域顶部，不单独渲染成远离列表的大卡片。
- 搜索打开与关闭使用同一个图标按钮位置，通过按钮状态表达当前是“打开搜索”还是“关闭搜索”。
- 查询区应使用统一边框、浅背景和紧凑表单布局。
- 查询条件优先按网格布局组织，不直接堆成自由流式排列。
- 查询字段标签、输入控件、操作按钮必须对齐。
- 查询区按钮顺序统一为：`重置`、`查询`。
- 查询条件变化后发起查询，分页列表应回到第 `1` 页。
- 字段不足一行时不应为了形式强行保留展开/收起副按钮。

### 9.4 管理列表工具栏

- 管理列表工具栏位于筛选区下方、表格上方。
- 工具栏左侧承载业务操作，如 `新增`、`批量删除`、`批量禁用`、`导出`。
- 工具栏右侧承载查询工具，如 `打开/关闭搜索`、`刷新列表`。
- 业务操作按钮使用文字按钮，查询工具按钮使用图标按钮，两类操作必须在视觉上有明确区分。
- 工具栏不放置重复标题。列表名称可作为页面标题或当前区域标题存在，不在工具栏中反复强调。
- 业务操作过多时，应通过统一的“更多 / 收起”能力收敛，而不是换行挤压查询工具区或表格宽度。

### 9.5 主内容区

- 主内容区通常使用统一管理列表容器承载。
- 表格外层应具备清晰边框和轻微圆角。
- 表格列宽、复选框列、操作列、滚动条和分页区域必须稳定。
- 空状态、加载状态、错误状态、批量选择状态和分页状态必须有统一视觉规则。

## 10. 导航与壳层规范

### 10.1 侧边栏

- 侧边栏展开宽度基线为 `224px`，收起宽度基线为 `72px`。
- 激活项使用主色边框、浅蓝背景和蓝色文字。
- 非激活项 hover 使用浅灰或浅蓝背景。
- 菜单层级通过缩进体现，不依赖过多装饰线。
- 图标、标题和展开箭头必须对齐，收起态保持图标居中。

### 10.2 顶部区域

- 顶部栏保持轻量、扁平和低干扰。
- 仅放置导航辅助、系统入口、用户信息、必要工具按钮。
- 不在顶部栏叠加与当前页面强绑定的业务内容。

### 10.3 标签栏

- 标签栏只承担多页面切换语义。
- 标签名称使用清晰业务名，不拼接冗余状态说明。
- 当前标签态与可关闭态必须有稳定视觉差异。

## 11. 表格与管理列表页设计规范

### 11.1 总体定位

- 后台管理列表默认采用“Excel 风格管理列表”。
- 管理列表重点是规整、稳定、可扫读、高密度和低干扰，不依赖大卡片、大留白或强装饰表达层级。
- 表格、工具栏、筛选区、批量操作区和分页区应作为同一个数据区域整体设计。
- 后台表格统一优先使用 `BzTable`；需要管理列表能力时，应在 `BzTable`、`BzPagination`、`AdminActionBar`、`AdminTableTools` 等通用能力基础上扩展，不允许单页手写一套新表格。
- 列表页、树形列表页、分页选择列表、审计日志列表、登录日志列表、资源列表、字典列表等同类场景，应优先使用同一套管理列表结构。

### 11.2 标准管理列表结构

管理列表默认由以下区域组成：

```text
筛选条件，可收起，默认收起
工具栏：左侧业务操作，右侧查询工具
表格主体：预留选择列 + 数据列 + 操作列
分页区：分页列表需要；树形全量列表可不需要
```

要求：

- 筛选条件、工具栏、表格主体和分页区应在视觉上形成一个连续的 Excel 风格区域。
- 不再推荐将筛选条件、列表标题和结果表格拆成多个相互割裂的大卡片。
- 表格主体应使用细边框、弱表头背景、稳定行高和低对比度分割线。
- 表格区域不使用明显阴影。
- 页面背景、列表容器、表格头部和分页区应保持克制，不使用大面积强色块。
- 同一页面中若存在多个列表区域，每个列表区域应使用同一套标题、工具栏、表格和分页规则。

### 11.3 筛选条件区域

- 筛选条件默认收起。
- 用户点击查询工具区中的搜索图标按钮后，筛选条件展开；再次点击同一个按钮后收起。
- 搜索打开与关闭不得使用两个并列按钮占用两个位置。
- 筛选区展开或收起时，不应造成工具栏、表头列宽、分页区和表格滚动位置抖动。
- 筛选区字段名称应业务清晰，不使用含混词汇。
- 搜索框 placeholder 必须说明搜索范围，如 `搜索编码 / 名称`、`搜索资源名称 / 编码 / 路径 / 组件`。
- 筛选条件优先按网格布局组织，桌面端建议 `3 到 4` 列。
- 查询区操作按钮统一使用 `重置`、`查询`。
- 查询条件变化、点击查询、修改 pageSize 后，分页列表应回到第 `1` 页。
- 筛选区关闭不代表清空筛选条件；清空必须通过 `重置` 明确触发。
- 对于简单列表，筛选条件为空时可默认收起并只保留搜索图标入口。

### 11.4 工具栏布局

工具栏分为左侧业务操作区和右侧查询工具区。

```text
┌──────────────────────────────────────────────┐
│ 新增 批量删除 批量禁用 导出 更多      🔍  ↻ │
└──────────────────────────────────────────────┘
```

要求：

- 左侧业务操作区承载会改变业务数据或导出业务数据的操作。
- 右侧查询工具区承载搜索开关、刷新列表等查询辅助操作。
- 业务操作按钮使用文字按钮。
- 查询工具按钮使用 icon 按钮。
- 两类按钮不得混用样式，避免用户误判操作性质。
- 工具栏高度应稳定，不因按钮数量、搜索开关状态或刷新状态发生明显变化。
- 查询工具区应始终靠右，不能被业务按钮挤压到换行或消失。
- 工具栏不放置与当前区域含义重复的标题文案；区域标题应在页面标题或表格容器标题中处理。

### 11.5 业务操作按钮收敛

业务操作按钮数量较多时，默认显示高频主操作，其余进入统一收敛区。

规则：

- 当业务操作按钮整体宽度不超过工具栏可用宽度的一半时，可以全部直出。
- 当业务操作按钮超过工具栏可用宽度的一半，或会挤压右侧查询工具区时，必须收敛低频操作。
- 收敛入口文案使用 `更多` 或 `更多操作`。
- 展开后入口文案切换为 `收起`。
- 展开区位于工具栏下方，与当前列表区域视觉相连。
- 展开区内按钮仍使用文字按钮，不改成图标按钮。
- 展开区内按钮顺序必须与未收敛时的业务顺序一致。
- 危险操作进入展开区后仍保持危险语义。
- 收敛逻辑应由通用组件统一处理，不允许不同页面各自计算和渲染不同的更多区。

### 11.6 查询工具按钮

查询工具按钮用于搜索开关、刷新列表、列设置、密度设置等查询或展示辅助能力。

要求：

- 搜索开关使用单个 icon 按钮承载打开和关闭两种状态。
- 搜索关闭状态：按钮表达“打开筛选条件”。
- 搜索打开状态：按钮表达“关闭筛选条件”，并可使用浅色激活背景。
- 刷新按钮只刷新当前列表数据，不清空当前筛选条件。
- 查询工具按钮应提供 `title`、`aria-label` 或等价说明。
- 查询工具按钮尺寸应稳定，通常与普通按钮高度一致。
- 查询工具按钮不承载新增、删除、导出等业务动作。

### 11.7 复选框列预留规则

所有管理列表都应预留选择列位置。

要求：

- 表格第一列固定为选择列。
- 如果当前场景没有批量操作或没有进入批量模式，选择列仍保留宽度，但不显示复选框。
- 进入批量模式后，表头选择列显示全选复选框，数据行选择列显示行选择复选框。
- 复选框显示或隐藏不得导致数据列整体右移。
- 选择列宽度应固定，建议 `40px ~ 48px`。
- 表头全选复选框只对当前可见数据或当前页数据生效，除非业务明确支持全量跨页选择。
- 当前页部分选中时，全选复选框应显示半选状态。
- 选中行可使用浅色背景反馈，不使用重色块。

### 11.8 批量操作交互

批量删除、批量禁用、批量导出等操作进入二阶段批量模式。

交互规则：

- 用户点击批量操作按钮后，立即进入批量模式。
- 进入批量模式后，普通业务操作按钮应隐藏。
- 工具栏区域替换为批量操作提示，如 `批量删除中`、`批量导出中`。
- 批量操作提示后展示已选数量。
- 批量模式右侧展示 `确认`、`取消`。
- 进入批量模式后，表格选择列立即显示复选框。
- 批量模式不应改变表格列宽。
- 批量模式不应改变操作列宽。
- 点击 `取消` 后退出批量模式，清空当前批量选择。
- 点击 `确认` 后按操作类型执行后续确认或提交。
- 危险批量操作，如批量删除，点击 `确认` 后仍必须进行二次确认。
- 批量导出若允许无选择时导出全部，必须在文案中明确；否则未选择数据时确认按钮应禁用。
- 批量模式下可保留右侧查询工具，但不能允许用户执行会破坏批量上下文的操作；如刷新会清空选择，应先二次确认或禁用刷新。

推荐结构：

```text
批量删除中  已选 3 项                         确认  取消
┌────┬────────┬────────┬──────────────┬──────┐
│ ☑  │ 列 A   │ 列 B   │ ...          │ 操作 │
├────┼────────┼────────┼──────────────┼──────┤
│ ☑  │ 数据行 │ 数据行 │ ...          │ 操作 │
└────┴────────┴────────┴──────────────┴──────┘
```

### 11.9 列宽稳定规则

列宽稳定是管理列表的硬性规则。

要求：

- 每一列都必须有明确宽度。
- 翻页、刷新、筛选、进入批量模式、退出批量模式、出现空值或长文本时，列宽不得变化。
- 即使某一列当前页完全没有值，也不得让其它列吞占该列宽度。
- 表格实现应使用固定列宽策略，而不是依赖内容自动撑开列宽。
- 如果需要自适应布局，最多允许一个列作为弹性列，占用剩余宽度。
- 弹性列必须明确指定，不能由浏览器或表格自动随机分配。
- 操作列、选择列、状态列、类型列、时间列、编码列等应固定宽度。
- 长文本列、备注列、描述列可作为弹性列，但同一表格只能有一个主要弹性列。
- 不允许因为接口返回字段顺序或内容长度变化导致列顺序、列宽或表头布局漂移。
- 同一业务模块内的同类列表应尽量保持列顺序和列宽一致。

### 11.10 单元格内容溢出策略

表格组件必须支持单元格溢出策略配置。

推荐策略：

| 策略 | 说明 | 适用字段 |
| --- | --- | --- |
| `ellipsis` | 单行截断，hover 显示完整内容 | 名称、编码、路径、组件路径、IP、User-Agent |
| `wrap` | 自动换行，行高随内容撑开 | 描述、备注、错误信息、长说明 |
| `nowrap` | 不换行，保持单行完整展示，必要时横向滚动 | 操作按钮组、短状态、短编码 |
| `pre-wrap` | 保留换行和空格 | JSON 片段、请求报文、错误堆栈 |

要求：

- 默认列表单元格建议使用 `ellipsis`。
- 备注、描述、错误信息等可按业务需要使用 `wrap`。
- 截断内容必须支持查看完整内容。
- 完整内容浮层中的文本必须可选择、可复制。
- 完整内容浮层不应只用原生 `title`，应优先使用 `BzOverflowTooltip` 或统一可复制 tooltip。
- 正常显示、截断显示、浮层显示中的文本内容必须一致。
- 空值统一显示 `-`，不使用空白、`null`、`undefined`。
- 技术型字段优先使用等宽字体。

### 11.11 行高稳定与高度变化

- 表格默认行高应稳定，建议 `40px ~ 48px`。
- 列宽不可因翻页变化，但行高允许因单元格内容换行而变化。
- 使用 `wrap` 的列可以撑高当前行。
- 同一行内所有单元格高度必须一致。
- 操作列按钮应垂直居中。
- 不允许固定高度导致长文本被遮挡。
- 如果业务要求列表密度稳定，可统一使用 `ellipsis`，将完整内容交给 tooltip 或详情页。

### 11.12 操作列规则

操作列用于承载单行操作，默认位于表格最右侧。

要求：

- 操作列必须优先保证宽度。
- 操作列宽度必须固定，不受其它列挤压。
- 操作列文字按钮不允许换行。
- 开发时应主动避免超长操作文案。
- 组件自身必须支持超长操作按钮：超长按钮不换行，可截断并配合 tooltip 或收进 `更多`。
- 操作列优先通过 `AdminActionBar` 承载。
- 操作列只展示当前角色拥有权限的操作；无权限操作不可见，不参与按钮数量计算。
- 当前角色拥有权限但因业务规则不可执行的操作，应展示为禁用态。
- 禁用态点击不得触发弹窗、抽屉、接口请求、二次确认或任何业务副作用。
- `更多` 菜单中的操作同样必须遵循权限可见性、业务禁用态和危险操作规则。
- 操作列在横向滚动时必须冻结在右侧。

### 11.13 固定列与横向滚动

当列表列数较多或列宽总和超过容器宽度时，必须支持横向滚动。

要求：

- 表格容器应支持水平滚动。
- 列宽总和超过容器宽度时，不强制压缩所有列。
- 支持配置左侧冻结列和右侧冻结列。
- 选择列通常冻结在左侧。
- 关键识别列，如名称、账号、编码，可按业务需要冻结在左侧。
- 操作列必须冻结在右侧。
- 冻结列应有细边框或弱阴影提示层级，但不应使用重阴影。
- 冻结列与滚动列的行高必须同步。
- 不允许为了实现冻结列而在页面中拼接两套不同表格。
- 横向滚动时，表头、内容行、底部分页区域不得错位。
- 树形列表使用横向滚动时，缩进、展开图标和冻结列必须保持对齐。

### 11.14 滚动条与防抖动规则

所有可能出现滚动条的区域，都必须预留滚动条位置。

要求：

- 水平滚动条和垂直滚动条都应使用稳定滚动条策略。
- 推荐使用 `scrollbar-gutter: stable` 或等效实现。
- 表格容器在内容未溢出时，也应保持不会因滚动条出现而改变内容宽度。
- 查询区展开、批量模式进入、分页变化、空状态切换、加载状态切换时，不应导致表格列宽或页面主体横向抖动。
- 表格最大高度可按页面场景设置；超过后在表格内部滚动，不让整个页面结构跳动。
- 浮层、抽屉中的表格也必须预留滚动条位置。
- 禁止因为新增一条数据、展开一条长文本、进入批量选择或刷新加载状态导致已有内容整体移动。

### 11.15 表头、排序与列筛选

- 表头背景应与正文略有区分，但不应过重。
- 表头文字应简洁，不使用长说明文案。
- 支持排序的列必须有明确视觉提示和可点击反馈。
- 不支持排序的列不得展示排序图标或伪交互。
- 列级筛选必须使用统一样式，不允许某一列单独实现一套悬浮筛选 UI。
- 表头吸顶在长列表和固定高度表格中允许作为通用能力支持。
- 表头吸顶不得破坏列宽、冻结列和横向滚动对齐。

### 11.16 列内容规则

- 名称类字段左对齐。
- 编码、路径、权限码、组件路径、追踪 ID、请求 ID、IP、User-Agent 优先使用等宽字体。
- 布尔值优先明确显示 `是 / 否`、`启用 / 停用`、`允许 / 禁止`。
- 状态类字段使用统一 `BzTag` 或统一颜色语义。
- 数字、计数、金额字段应在同一页面保持统一对齐方式。
- 时间字段在同一页面和同一模块内必须使用统一格式；无特殊要求时优先使用 `YYYY-MM-DD HH:mm:ss`。
- 路径、组件路径、接口地址等长技术字段默认使用 `ellipsis + 可复制 tooltip`。
- 说明、备注、失败原因等业务长文本可使用 `wrap` 或 `ellipsis`，由列定义明确指定。

### 11.17 树形列表

树形列表用于展示目录、菜单、资源、组织、分类、权限树等层级数据。

要求：

- 树形列表默认不分页，除非业务数据量极大且后端提供明确的分页树能力。
- 树形列表仍使用 Excel 风格表格，不使用多层卡片。
- 树形展开/收起按钮使用统一 SVG 图标或统一箭头组件。
- 缩进只表达层级，不应挤压主要文本可读空间。
- 每一级缩进应使用稳定步长，建议 `20px ~ 24px`。
- 叶子节点与父节点图标尺寸和位置应一致。
- 树节点名称所在列应固定宽度或作为唯一弹性列。
- 类型、编码、路径、组件路径、状态、排序、操作等信息应放入独立列。
- 树形列表过滤后如自动展开命中链路，应保证节点和操作列仍然对齐。
- 树形列表进入批量模式时，同样显示预留选择列，不改变树节点缩进和列宽。
- 父子选择关系由业务规则决定，但视觉交互应保持一致。

### 11.18 分页列表

分页列表用于远程分页数据、日志数据、管理对象列表和关联对象选择等场景。

要求：

- 分页统一优先使用 `BzPagination`。
- 分页区域位于表格底部，与表格视觉相连。
- 总数说明放在左侧或分页区域的稳定位置。
- 常规列表默认页大小优先从 `10` 开始。
- 模块一旦确定 pageSize 选项，应在本模块内保持一致。
- 查询条件变化或 pageSize 变化后，应回到第 `1` 页。
- 列表刷新后默认保留当前页和当前筛选条件。
- 若当前页因数据变化越界，应自动回退到最后有效页。
- 翻页时列宽不得变化。
- 翻页时允许行高因内容换行而变化。
- 加载下一页时应在表格区域内展示局部 loading，不应导致整个页面重新布局。
- 分页区域的高度和位置应稳定，不因页码数量变化明显抖动。

### 11.19 空状态、加载状态与错误状态

- 空状态默认文案使用 `暂无数据`，特殊场景可替换为更明确的业务空态文案。
- 搜索无结果与初始无数据可使用不同文案，但风格必须统一。
- 空状态应出现在表格主体区域内，不破坏工具栏和分页区域结构。
- 加载状态应限制在列表区域内。
- 加载状态不应改变列宽、操作列宽、选择列宽和分页位置。
- 错误状态应在列表区域内展示明确原因和重试入口。
- 错误状态不应只通过全局 message 表达。
- 空状态、加载状态、错误状态的最小高度应稳定，避免区域剧烈跳动。

### 11.20 管理列表场景选择

不同数据形态应使用对应的管理列表方案：

| 数据类型 / 场景 | 推荐方案 | 分页规则 |
| --- | --- | --- |
| 普通管理对象列表 | 分页管理列表 | 默认分页 |
| 日志列表 / 审计列表 | 分页管理列表 | 默认分页 |
| 字典、配置、枚举等列表 | 分页管理列表或少量静态列表 | 数据可能增长时分页 |
| 资源、菜单、组织、分类等层级数据 | 树形管理列表 | 默认不分页 |
| 关联对象选择列表 | 分页选择列表 | 默认分页，并保留跨页已选项 |
| 批量维护列表 | 批量模式管理列表 | 分页与树形均可支持 |
| 多列技术数据列表 | 横向滚动 + 冻结列管理列表 | 按数据量决定是否分页 |

要求：

- 选择方案时以数据结构为准，不以具体页面名称为准。
- 同一种数据结构在不同业务页面中应优先使用同一种列表方案。
- 页面不得因为临时字段较少而改成卡片堆叠，后续字段增长会导致风格漂移。
- 对外观确有特殊要求的列表必须登记例外。

### 11.21 通用实现要求

管理列表能力应沉淀为通用组件或通用组合，而不是页面内硬编码。

通用能力至少应支持：

- 筛选区默认收起。
- 单个搜索 icon 按钮控制筛选区打开 / 关闭。
- 左侧业务操作区。
- 右侧查询工具区。
- 业务操作按钮收敛。
- 批量操作二阶段模式。
- 复选框列预留。
- 固定列宽。
- 单一弹性列。
- 单元格溢出策略。
- 可复制完整文本 tooltip。
- 横向滚动。
- 左侧冻结列。
- 右侧冻结操作列。
- 稳定滚动条预留。
- 分页列表。
- 树形列表。
- 空状态、加载状态、错误状态。

要求：

- 业务页面只配置列、数据、权限、操作和查询条件。
- 列表容器、工具栏、批量模式、滚动条、固定列和溢出策略由通用组件统一处理。
- 新增页面不得因为列数量、操作数量或数据类型不同而复制一套相似但不一致的表格结构。

## 12. 操作按钮规范

### 12.1 操作按钮顺序

默认推荐顺序：

1. 详情
2. 编辑/维护
3. 启用/停用
4. 重置/复制/其他常规操作
5. 删除

要求：

- 危险操作尽量靠后。
- 同一页面同类表格必须保持相同操作顺序。

### 12.2 操作按钮数量约定

- 操作按钮数量按“当前角色有权限看到的操作”计算；无权限操作不可见，不参与数量计算。
- 当行操作按钮数量小于等于 3 时，全部直出。
- 当行操作按钮数量大于 3 时，仅保留前 2 个直出。
- 第 3 个及其后续操作统一收进 `更多`。
- `更多` 本身视为操作列中的统一收敛入口，不算作额外例外。
- 被收进 `更多` 的操作仍需保持原有顺序、危险语义和禁用态。
- 该规则由 `AdminActionBar` 统一承载，页面不得各自实现不同逻辑。

### 12.3 权限可见性与禁用态规则

- 无权限导致不可操作：隐藏。
- 有权限但业务不可用：禁用。
- 禁用态按钮必须具有明确的灰化视觉表现。
- 禁用态不能只靠颜色表达，还应结合禁用鼠标样式、透明度和不可点击行为。
- 禁用态点击不得触发弹窗、抽屉、接口请求、二次确认或任何业务副作用。
- 隐藏态与禁用态必须按原因区分，禁止混用。

适合禁用显示的场景：

- 记录状态导致不可编辑、不可删除、不可启用或不可停用。
- 系统内置对象不允许删除。
- 该资源类型不存在下级创建能力。
- 上游状态未满足，当前操作暂不可执行。

### 12.4 危险操作

- 删除、批量删除、强制下线、重置密码、重置密钥、清空配置等不可逆或敏感操作必须二次确认。
- 删除按钮颜色保持红色语义，不能与普通按钮同色。
- 危险操作即使被收进 `更多`，也必须保留危险语义和确认流程。

## 13. 表单设计规范

### 13.1 基本规则

- 后台表单统一使用 `BzForm`、`BzFormItem` 和 `Bz*` 输入组件。
- 表单项优先按两列或单列网格排列。
- 字段标签与控件之间要保持稳定间距。
- 同一区域内输入框、下拉框、开关、标签文字必须高度协调。
- 禁止出现同一行多个控件高度明显不一致的情况。

### 13.2 必填项与 placeholder 规则

- 在当前 `BzFormItem` 未内置必填标记能力的前提下，必填项统一通过标签文案显式展示 `字段名 *`。
- 表单中的必填字段必须在字段标签后展示必填标识 `*`。
- 必填标识 `*` 必须使用统一危险色/错误色展示，不得使用普通正文色、灰色或弱化色。
- 必填标识应紧跟字段标签展示，与标签保持同一行、同一基线。
- 必填标识只表达“该字段必填”，不表达字段校验失败。
- 只读展示场景原则上不展示必填标识；只有处于可编辑表单中的必填输入项才展示 `*`。
- 不允许同一后台中同时混用红星、括号必填、图标必填等多套规则。
- 输入框 placeholder 使用“请输入 + 字段名”。
- 下拉框 placeholder 使用“请选择 + 字段名”。
- 搜索框 placeholder 必须说明搜索范围，如“搜索角色编码/名称”“按账号或昵称搜索”。

### 13.3 校验与错误反馈

- 必填、格式错误、长度限制等校验必须在提交时统一执行。
- 可根据业务需要在失焦时提前校验，但不建议用户每输入一个字符就频繁弹错。
- 字段校验失败应通过错误文案、错误边框或错误状态表达，不得仅依赖必填星号变化表达错误。
- 字段级错误优先显示在字段附近；当前组件能力不足时，可在表单区顶部使用 `BzAlert` 明确展示。
- 抽屉或弹窗内提交失败时，应优先让用户在当前浮层内看到错误，而不是只弹全局 message。
- 后端字段错误应尽量回填到对应字段或当前表单错误区。
- 非字段级错误可展示在表单顶部、抽屉内提示区或全局 message，但同类错误处理方式必须一致。

### 13.4 提交、关闭与重复点击规则

- 保存按钮在提交中必须进入 `loading` 或禁用态，防止重复提交。
- 提交中不应允许通过重复点击再次发起请求。
- 新增、编辑保存成功后，默认关闭抽屉或弹窗并刷新列表。
- 如业务要求保存后停留当前页继续编辑，必须在页面说明或需求中明确，不作为默认行为。
- 表单已修改但未保存时，是否拦截关闭必须按页面复杂度统一。
- 简单表单可不拦截关闭。
- 配置型、步骤型、长表单型抽屉建议拦截关闭或进行二次确认。

### 13.5 只读、禁用、隐藏字段区分

- 只读：字段需要展示，但用户不可编辑。
- 禁用：字段在当前上下文存在，但当前不可编辑。
- 隐藏：字段在当前场景不应出现，或当前用户无权限查看。
- 只读态不能看起来像报错态。
- 隐藏字段不得通过占位空白破坏布局。

## 14. 抽屉与弹窗规范

### 14.1 选择规则

- 列表行维护、配置编辑、较复杂表单优先使用抽屉。
- 简短确认、简单录入、轻量配置可以使用弹窗。
- 内容较多、需要滚动或多分组展示时，必须优先使用抽屉。

### 14.2 抽屉规范

- 复杂维护统一优先使用 `AdminEntityDrawer`。
- 抽屉默认宽度基线优先使用 `920px`、`960px`、`1120px` 等稳定档位。
- 抽屉内容区应独立滚动，footer 固定在底部。
- 抽屉面板内分组应使用清晰边框、浅背景或统一面板容器承载。

### 14.3 弹窗规范

- 简短确认和轻量录入统一优先使用 `BzDialog`。
- 弹窗宽度根据内容复杂度控制在稳定档位，常规表单对话框优先在 `520px` 左右。
- 不允许为了容纳复杂配置而把弹窗无限增高增宽，复杂内容应转为抽屉。

### 14.4 标题规则

- 抽屉和弹窗顶部只展示动作标题。
- 标题示例：`编辑资源`、`用户维护`、`角色权限分配`、`详情`。
- 不在标题区拼接用户名、编码、路径、资源标识等业务数据。

### 14.5 内容分组规则

- 抽屉内容必须按业务语义分组。
- 推荐分组示例：基础信息、路由信息、状态配置、权限绑定、角色分配、高级配置。
- 每个分组必须有独立承载区域，如卡片或浅边框区块。
- 分组标题与字段内容之间要有明确间距。
- 分组之间要有明显留白。
- 详情态与编辑态应尽量共用结构布局，只调整交互能力。

### 14.6 footer 规则

- 无编辑能力时，底部按钮使用 `关闭`。
- 可编辑时，底部按钮使用 `取消 + 保存`。
- 确认型二阶段流程允许使用 `返回 + 确认`。
- footer 按钮顺序必须稳定，主按钮放在右侧收尾位置。

### 14.7 关闭与 Esc 规则

- 当前 `BzDialog` 支持 `Esc` 和遮罩关闭能力，但涉及未保存内容或危险操作时，不能直接关闭造成数据丢失。
- 抽屉和弹窗关闭后，焦点应尽量回到触发入口。
- 打开后应优先聚焦到标题、首个可输入字段或主要操作区域。

## 15. 详情页与只读展示规范

### 15.1 展示风格

- 后台详情页、只读信息页、编辑页中的只读信息区，默认统一使用“Excel 风格详情表格”展示。
- 不再推荐“每个字段一个独立卡片”的展示方式，除非该页面已登记例外。
- 重点是规整、稳定、可扫读、紧凑，而不是依赖大卡片、大留白或强装饰表达层级。
- 详情内容不应通过输入框伪装，只读信息应直接展示为字段表格。
- 当详情页或编辑页中出现列表明细、状态配置、层级配置、关联对象选择等复杂区域时，同样应延续 Excel 风格的表格化表达，不应退化为大卡片、分散列表或自由排版。
- 当前项目详情展示的默认通用实现基线为 `AdminDetailTable`。

### 15.2 字段组织

- 同一类信息必须归入同一个信息分组。
- 用户标识、资源标识、系统属性等归入 `基础信息` 组。
- 状态类、行为类、统计类、请求类、说明类、返回类等信息应分别归入独立分组。
- 编辑页中的“只读信息”“历史信息”“系统生成信息”等区域，同样遵循本章节规则，不允许单独实现另一套只读展示风格。
- 列表型只读信息，如明细项、权限码、按钮列表、关联对象列表、历史记录等，应优先使用表格化列表展示；若展示为字段形式，仍应优先使用统一详情表格。
- 配置型信息，如布尔开关、状态项、系统标记等，应归入独立配置分组，不应散落在基础字段中。
- 层级型信息，如目录、资源、菜单、分类、权限树等，应使用树形表格或树形选择表格表达层级，不应通过多层卡片嵌套表达层级。
- 关联型信息，如角色、用户、资源、标签等多选绑定关系，应使用关联选择表格表达，数据量较大时必须支持查询与分页。
- 与当前对象无关的分组不应渲染占位空块。
- 同一业务对象在不同页面中的字段分组名称和字段顺序应尽量一致，避免用户切换页面后认知跳变。

### 15.3 标准结构

后台详情区默认遵循以下结构：

1. 抽屉标题或弹窗标题
2. 信息分组 A
3. 信息分组 B
4. 信息分组 C

每个普通字段信息分组内部使用统一详情表格展示：

```text
分组标题
┌────────┬────────┬────────┬────────┬────────┬────────┐
│ 属性名 │ 属性值 │ 属性名 │ 属性值 │ 属性名 │ 属性值 │
├────────┼────────┼────────┼────────┼────────┼────────┤
│ 属性名 │ 属性值 │ 属性名 │ 属性值 │ 跨列属性值区域        │
└────────┴────────┴────────┴────────┴────────┴────────┘
```

复杂数据分组可在同一视觉体系下扩展为：

```text
分组标题 + 统计/轻操作
┌────────────────────────────────────────────┐
│ 查询区 / 工具区，可选                       │
├────────┬────────┬────────┬────────┬────────┤
│ 表头   │ 表头   │ 表头   │ 表头   │ 表头   │
├────────┼────────┼────────┼────────┼────────┤
│ 数据行 │ 数据行 │ 数据行 │ 数据行 │ 数据行 │
└────────┴────────┴────────┴────────┴────────┘
分页 / 已选摘要，可选
```

要求：

- 每个分组独立成表或独立成一个表格化区域。
- 分组之间保留稳定间距，但间距不应大到造成页面松散。
- 标题、表格、边框、行高、单元格规则在同一页面内必须一致。
- 复杂区域可以有查询、分页、已选摘要和轻量操作，但这些能力必须附着在同一个分组区域内，不应漂浮到页面其它位置。

### 15.4 分组标题规则

- 每个信息分组必须有标题。
- 标题应位于表格上方或作为表格区域的首行标题区，不应设计成大卡片头。
- 标题需加粗，但不应过大。
- 标题与表格必须视觉上属于同一区域。
- 多个分组的标题样式必须保持一致。
- 分组标题右侧可展示轻量统计信息，如 `共 2 项`、`已选 3 项`、`67 / 71 项`。
- 分组标题右侧只放置与当前分组强相关的轻操作或统计，不放置跨页面主操作。
- 推荐标题语义：`基础信息`、`请求信息`、`状态信息`、`说明信息`、`审计摘要`、`请求与响应`、`状态配置`、`权限内容`、`关联对象`。

### 15.5 表格布局规则

#### 15.5.1 基础单元结构

- 每个字段由两个单元格组成：`属性名单元格 + 属性值单元格`。
- 属性名和属性值必须成对出现，不允许只渲染值不渲染属性名。

#### 15.5.2 每行字段数量

- 桌面端建议每行展示 `2 到 3` 个字段组合。
- 但不强制每一行展示相同数量的字段。
- 字段数量应由容器宽度和字段跨度自动决定，而不是每个页面手写固定布局。

#### 15.5.3 列对齐规则

- 同一分组表格内所有列必须对齐。
- 一旦当前分组确定了列结构，后续每一行都必须沿用同一列结构。
- 禁止出现某一行列宽错乱、字段和值无法纵向对齐的情况。
- 属性名列宽应相对固定，属性值列可弹性占据剩余空间。

#### 15.5.4 合并单元格规则

- 当某一行字段数量少于该表格标准列数时，必须通过跨列合并保持整体结构对齐。
- 不允许留下悬空空格或错位单元格。
- 长文本字段、备注字段、描述字段、路径字段、请求报文等内容，允许让属性值单元格跨多列。
- 单独占一行的重要字段应采用：`属性名 + 横向合并后的属性值区域`。
- 当前项目默认通用规则：当一行未填满时，将剩余列自动合并到该行最后一个属性值单元格。

### 15.6 单元格样式规则

#### 15.6.1 属性名单元格

- 属性名单元格使用浅灰或弱背景色。
- 文字颜色使用辅助文字色或次级文字色。
- 字重略高于普通正文，但不应过重。
- 内容左对齐、垂直居中。
- 宽度相对固定。
- 不单独使用圆角、阴影或额外边框包裹。

#### 15.6.2 属性值单元格

- 属性值单元格使用白色或主内容背景色。
- 文字颜色使用主要文字色。
- 默认左对齐。
- 金额、数量、比例等数字型字段可按业务需要右对齐。
- 支持自动换行。
- 与属性名单元格共用同一套边框系统。

#### 15.6.3 边框与圆角

- 表格使用细边框。
- 外边框与内边框风格一致。
- 边框对比度应低，不应过重。
- 不使用明显阴影。
- 整个分组表格外层可以有轻微圆角。
- 单元格内部不需要单独圆角。
- 不再使用“每个字段一个独立圆角卡片”的视觉风格。

### 15.7 行高与多行内容规则

- 单元格最小高度建议为 `40px ~ 48px`。
- 同一行内所有单元格高度必须一致。
- 某一单元格内容较长时，该整行高度应自动撑高。
- 长文本、备注、描述、地址、路径、报文、错误信息等字段默认允许换行。
- 长文本字段可以单独占一行，并让属性值跨满剩余列。
- 不允许固定高度导致长文本被遮挡。
- 表格化复杂区域中的表头、数据行、选择行和树节点行，也应沿用同一行高基线。

### 15.8 空值、状态值与技术字段规则

- 空值统一展示为 `-`。
- 不得使用空白、`null`、`undefined` 或省略字段导致布局塌陷。
- 状态类字段可以使用轻量标签展示，但标签尺寸必须小巧，不应破坏整行高度。
- 编码、路径、权限码、会话 ID、请求 ID、追踪 ID、User-Agent、JSON 片段等技术型字段优先使用等宽字体。
- 技术型长文本可在详情表格单元格中直接换行，也可配合 `pre` 风格容器展示。
- 复杂区域中的编码列、权限码列、路径列、组件路径列、更新时间列应保持格式统一，不同数据行之间不得随机变化。

### 15.9 字段排序规则

- 关键识别字段优先展示。
- 状态、类型、编号、时间等摘要字段靠前。
- 说明、备注、描述、报文、错误信息等长文本字段靠后。
- 长文本字段优先位于行尾或单独占一整行。
- 同一业务对象在不同页面中的字段顺序必须尽量稳定，不应随接口返回顺序随机漂移。

### 15.10 响应式规则

- 桌面端：优先每行 `3` 组字段。
- 平板端：优先每行 `2` 组字段。
- 手机端：降为每行 `1` 组字段，但仍保持表格风格，不退化为分散卡片。
- 窄屏下允许长文本继续跨整行。
- 响应式变化只能改变每行字段组数，不能改变字段分组规则、字段顺序和视觉语义。
- 表格化复杂区域在窄屏下优先横向滚动，不强制压缩关键列到不可读。
- 查询区、工具按钮、分页和已选摘要在窄屏下可换行或纵向堆叠，但仍必须位于当前分组内部。

### 15.11 编辑页中的详情内容规则

- 编辑页中如果存在“只读摘要”“基础只读信息”“系统信息”“历史信息”等展示区，统一按详情表格规则实现。
- 编辑页不得因为同时存在表单而把只读信息区改成另一种卡片堆叠样式。
- 推荐模式：
  - 可编辑字段使用 `BzForm`
  - 只读字段使用 `AdminDetailTable`
  - 列表型明细使用 `BzTable` 或基于统一样式封装的详情列表表格
  - 关联对象选择使用分页查询型关联选择表格
- 同一个抽屉中若同时存在编辑区和详情区，应通过“分组标题 + 表格/表单块”组织，不允许混杂成无结构的自由排版。
- 编辑页中的配置项、权限项、关联项虽然具备可编辑能力，但视觉上仍应服从本章的表格化分组规则。

### 15.12 通用实现要求

- 详情页实现必须优先基于通用组件，而不是页面内手写表格结构。
- 当前项目中，详情表格的默认通用组件为 `AdminDetailTable`。
- 表格化复杂区域应优先基于 `BzTable`、`BzPagination`、`BzCheckbox`、`BzTag`、`BzEmpty`、`BzLoading` 等组件组合沉淀通用能力。
- 通用数据结构至少应支持：
  - 分组标题
  - 字段标签
  - 字段值
  - 跨列能力
  - 对齐方式
  - 多行文本能力
- 表格化复杂区域的通用数据结构应按场景支持：
  - 列定义
  - 行数据
  - 状态标签
  - 选择状态
  - 树形层级
  - 查询条件
  - 分页信息
  - 已选摘要
- 新详情页不得绑定固定字段数量，不得因为字段增减而整体重写布局。
- 页面字段应以数据驱动方式喂给通用组件，再由组件自动排版成表格。
- 新增复杂详情区域时，应优先沉淀为通用组件或通用样式，不允许在单页复制一套相似但不一致的结构。

### 15.13 详情扩展区域场景选择

详情页、只读页和编辑抽屉中的非普通字段区域，应按数据类型选择展示方案：

| 数据类型 / 场景 | 推荐展示方案 | 适用说明 |
| --- | --- | --- |
| 少量基础字段 | 详情字段表格 | 编号、名称、类型、状态、时间、说明等普通属性。 |
| 列表型明细 | 详情列表表格 | 明细项、字典项、按钮项、权限码、历史记录、审计条目等多行同构数据。 |
| 状态 / 布尔配置 | 状态配置矩阵 | 可见、启用、系统内置、默认入口、允许访问等一组开关或状态项。 |
| 层级型配置 | 树形表格 / 树形选择表格 | 目录、菜单、资源、分类、权限树等存在父子层级的数据。 |
| 动作权限集合 | 树形表格 + 动作列 | 某一层级节点下包含多个按钮、动作、权限码或功能点。 |
| 关联对象选择 | 分页查询型关联选择表格 | 角色、用户、资源、标签、组织等需要多选绑定的数据，尤其是远程分页数据。 |

要求：

- 选择展示方案时以数据结构为准，不以具体页面名称为准。
- 同一种数据结构在不同业务页面中应优先使用同一种展示方案。
- 除普通基础字段外，其它复杂区域仍应保持“分组标题 + 表格化内容”的视觉结构。

### 15.14 列表型明细展示规则

列表型明细用于展示多行同构数据，如明细项、配置项、枚举项、按钮项、权限码、历史记录、审计条目等。

结构建议：

```text
分组标题 + 总数/刷新，可选
┌────────┬────────┬────────┬────────┬────────┐
│ 编码   │ 名称   │ 值     │ 状态   │ 备注   │
├────────┼────────┼────────┼────────┼────────┤
│ ...    │ ...    │ ...    │ ...    │ ...    │
└────────┴────────┴────────┴────────┴────────┘
```

要求：

- 表头必须明确列语义，不允许只用一列自由堆叠多项信息。
- 编码、值、路径、权限码等技术字段使用等宽字体。
- 状态列使用轻量 `BzTag` 或统一状态标签。
- 备注、描述等长文本列可换行，也可在列表场景下单行省略并配合 tooltip。
- 少量数据可不分页；数据可能增长、来自远程接口或超过当前浮层可扫读范围时，应使用分页。
- 空数据使用统一空态，不渲染空白表格区域。

### 15.15 状态配置矩阵规则

状态配置矩阵用于展示一组布尔值、开关项、系统标记或轻量状态项。

结构建议：

```text
状态配置
┌────────┬────────────────────────────────────┐
│ 状态项 │ ☑ 可见   ☑ 启用   ☐ 默认入口   ☑ 系统内置 │
└────────┴────────────────────────────────────┘
```

要求：

- 状态项应归入独立分组，不应混入基础信息字段中造成语义噪声。
- 状态项较少时可在同一行横向排列；状态项较多时应按语义拆分为多行。
- 只读状态可以使用禁用态复选框、轻量标签或明确文本，但同一页面内只能选择一套主要表达方式。
- 可编辑状态可以使用复选框或开关，但必须与只读状态有明确交互差异。
- 状态项之间保持稳定间距，不使用大卡片、大图标或重色块强调。
- 禁止使用输入框展示只读布尔值。

### 15.16 树形层级内容展示规则

树形层级内容用于展示具有父子关系的数据，如目录、菜单、资源、分类、组织节点、权限树等。

结构建议：

```text
分组标题 + 已选/总数
查询 / 展开 / 收起 / 清空，可选
┌────────────────────┬────────┬──────────────┬────────────────┐
│ 资源               │ 类型   │ 编码         │ 动作 / 权限项  │
├────────────────────┼────────┼──────────────┼────────────────┤
│ ▾ ☑ 一级节点        │ 目录   │ platform     │ -              │
│   ▾ ☑ 二级节点      │ 菜单   │ config       │ ☑ 查看 ☑ 编辑  │
└────────────────────┴────────┴──────────────┴────────────────┘
```

要求：

- 层级缩进只表达父子关系，不应挤压主要文本到不可读。
- 每一级缩进应使用稳定步长，建议 `20px ~ 24px`。
- 展开/收起图标、复选框、节点名称必须在同一行内垂直居中。
- 父节点、子节点、叶子节点必须使用同一套行结构，不允许父节点使用卡片、子节点使用表格。
- 类型、编码、状态、动作等辅助信息应放入独立列，避免全部堆入节点名称列。
- 动作或权限项较多时，应在动作列内自动换行，行高随内容撑开。
- 选中行可使用浅色背景反馈，但不使用重色块或强阴影。
- 支持搜索时，命中结果可自动展开上级链路，但不得改变列结构和缩进规则。

### 15.17 动作权限集合展示规则

动作权限集合用于表达某个对象或层级节点下的一组功能点、按钮权限、接口权限、操作权限等。

要求：

- 动作权限不应以分散按钮卡片展示，应放在表格的动作列或独立权限列中。
- 动作项可使用复选框、轻量标签或文本列表；同一业务区域内表达方式必须一致。
- 动作项文案使用业务动作名称，如 `查看`、`新增`、`编辑`、`删除`、`发布`、`停用`。
- 动作权限码、接口编码等技术信息如需展示，应使用等宽字体，并与动作名称建立清晰对应关系。
- 动作项数量较多时允许换行排列，不允许横向撑破容器。
- 如果动作项具备独立选择能力，勾选态必须清晰，且父子节点选择关系应与业务规则一致。

### 15.18 关联对象选择表格规则

关联对象选择表格用于编辑或维护某个对象与其它对象之间的绑定关系，如角色、用户、资源、标签、组织、数据范围等多选关联。

结构建议：

```text
分组标题 + 已选数量
查询条件：关键词 / 状态 / 类型 ... + 搜索 / 重置
┌────┬────────┬────────────┬────────┬──────────────┬────────┐
│ 选 │ 编码   │ 名称       │ 状态   │ 更新时间     │ 备注   │
├────┼────────┼────────────┼────────┼──────────────┼────────┤
│ ☑  │ code   │ name       │ 启用   │ 2026-01-01   │ -      │
└────┴────────┴────────────┴────────┴──────────────┴────────┘
已选摘要，可选
分页
```

要求：

- 关联对象数据量较大、来源为远程接口或存在搜索条件时，必须使用分页查询，不应一次性渲染完整列表。
- 分组标题右侧展示已选数量，如 `已选 2 项`。
- 查询区位于分组标题下方、表格上方，字段应说明搜索范围，如 `搜索编码 / 名称`。
- 查询条件变化、点击搜索或修改 pageSize 后，应回到第 `1` 页。
- 分页统一使用 `BzPagination`，分页区域位于表格底部，并与当前分组视觉相连。
- 当前页全选只影响当前页数据，不应误导为全量选择。
- 跨页已选项必须保留，不得因翻页、查询当前页或刷新当前页而丢失。
- 当已选项可能不在当前页可见范围内时，应提供已选数量；必要时展示已选摘要，如编码 / 名称标签。
- 已选行使用浅色背景反馈，不使用大面积强色块。
- 取消勾选当前页已选项后，应同步更新已选数量和已选摘要。
- 保存时以最终已选集合为准，而不是仅提交当前页勾选状态。

### 15.19 查询、工具栏与分页在详情分组中的规则

- 详情分组内部允许出现查询、刷新、展开、收起、清空选择、分页等轻量能力。
- 这些能力必须与当前分组直接相关，不应承载页面级主操作。
- 查询区和工具栏应保持紧凑，避免在抽屉或弹窗中占用过多垂直空间。
- 查询输入框、下拉框、按钮高度必须与当前后台表单和表格工具栏保持一致。
- 查询按钮、重置按钮、展开/收起按钮等顺序应沿用全局查询区和工具区规则，不在详情分组内自定义一套顺序。
- 分页、总数、当前页范围说明应固定在表格底部区域，不悬浮在表格中间。
- 数据刷新后应保留当前查询条件；若当前页越界，应回退到最后有效页。

### 15.20 空状态、加载状态与错误状态

- 列表型明细、树形内容和关联对象选择均必须有空状态。
- 初始无数据与搜索无结果可以使用不同文案，但风格必须一致。
- 远程分页查询时，加载状态应限制在当前分组内部，不阻断整个抽屉或页面。
- 查询失败、分页失败、关联对象加载失败时，应在当前分组内展示错误状态和重试入口。
- 空状态、加载状态、错误状态的区域高度应稳定，避免内容区域剧烈跳动。

### 15.21 复杂详情区域的推荐组件沉淀

后续如继续演进详情页复杂区域，建议按以下方向沉淀通用组件或通用样式：

| 场景 | 建议通用能力 |
| --- | --- |
| 普通字段详情 | `AdminDetailTable` |
| 列表型明细 | 详情列表表格组件，基于 `BzTable` 封装统一边框、行高、空态。 |
| 状态配置矩阵 | 状态配置矩阵组件，支持只读态和编辑态。 |
| 树形层级配置 | 树形选择表格组件，支持缩进、展开、勾选、动作列。 |
| 动作权限集合 | 权限动作列组件，支持换行、勾选、标签和禁用态。 |
| 关联对象选择 | 分页查询型关联选择组件，支持查询、分页、跨页保留选择和已选摘要。 |

要求：

- 通用组件应只暴露数据结构和必要交互回调，不要求业务页面手写表格 DOM。
- 视觉样式应由组件统一控制，业务页面只决定字段、列、数据和权限状态。
- 新增页面不得因为字段数量、列数量或动作项数量不同而重写一套视觉结构。

## 16. 权限、角色、资源类页面规范

### 16.1 层级信息表达

- 目录、菜单、功能、按钮等层级关系必须通过缩进、标签、树节点结构明确表达。
- 权限码、路径、组件路径等技术字段应保持紧凑且易区分。
- 树节点展开/收起图标必须统一，缩进节奏必须稳定。

### 16.2 授权与权限展示

- 如果后端语义是“功能授权”，按钮列表只是权限标识展示，则文案必须明确说明。
- 不得用界面暗示不存在的独立授权能力。
- 资源授权、角色授权、权限差异对比等场景优先复用统一树形与对比样式，不单页重造。

### 16.3 资源管理操作

- `新增子项` 这类与资源类型相关的操作，在业务上存在但当前行不可执行时，应显示禁用态。
- 系统内置资源不可删除时，应保持禁用而不是直接隐藏。
- 树形列表过滤后如自动展开命中链路，应保证节点和操作列仍然对齐。

## 17. 用户管理类页面规范

### 17.1 用户维护抽屉

- 标题使用动作名称，如 `用户维护`。
- 用户名、用户类型等标识信息放在基础信息组内。
- 昵称、状态等可编辑字段放在维护配置组内。
- 角色分配属于独立业务分组，不应与基础表单混在同一区块。

### 17.2 角色分配列表

- 支持搜索时，搜索框应位于分组头部下方。
- 已选数量可放在分组头部右侧。
- 角色列表项选中态要有清晰但不过度的高亮反馈。
- 无角色数据时应使用明确空态，如 `暂无角色`。

## 18. 查询、筛选与搜索规范

- 查询区字段名称应业务清晰，不使用含混词汇。
- 管理列表页查询区默认收起，通过列表工具栏右侧的搜索 icon 按钮打开或关闭。
- 搜索打开与关闭共用同一个按钮位置，不使用两个并列按钮。
- 查询区打开后位于当前列表区域顶部，并与表格、工具栏、分页视觉相连。
- 查询区必须提供 `查询` 与 `重置`。
- 查询按钮、重置按钮不应放入右侧查询 icon 工具区。
- 搜索框提示词必须说明搜索范围。
- 桌面端查询区优先使用 `3 到 4` 列网格。
- 平板端优先 `2` 列，手机端收敛为 `1` 列。
- 查询条件变化、点击查询或修改 pageSize 后，分页列表应回到第 `1` 页。
- 关闭查询区不清空查询条件；清空条件必须通过 `重置` 明确触发。
- 字段不足一行时不应为了形式强行保留展开逻辑。
- 高级筛选确需展开/收起时，文案统一使用 `展开` / `收起`，但不得与列表搜索开关重复表达。

## 19. 反馈、确认与错误处理规范

### 19.1 统一反馈通道

- 成功、轻量提示统一优先使用 `message`。
- 危险操作确认统一优先使用 `bzConfirm` 或基于 `BzDialog` 的统一确认能力。
- 表单区内错误优先使用当前浮层中的 `BzAlert`、字段错误提示或顶部提示区。
- 页面级错误应在页面主体区域明确展示，不只打印控制台或静默失败。

### 19.2 反馈与确认决策表

| 场景 | 默认反馈方式 | 规则 |
| --- | --- | --- |
| 新增成功 | `message.success` | 文案简洁，如“新增成功” |
| 保存成功 | `message.success` | 默认关闭浮层并刷新列表 |
| 删除成功 | `message.success` | 危险确认后执行 |
| 启用/停用成功 | `message.success` | 轻操作可直接执行后提示 |
| 删除/批量删除 | `bzConfirm` | 必须二次确认 |
| 重置密码/重置密钥/清空配置 | `bzConfirm` | 必须二次确认 |
| 表单校验失败 | 浮层内错误提示 | 优先定位字段或表单顶部提示 |
| 保存失败且需修改字段 | 浮层内错误提示 | 不只弹全局 message |
| 页面主数据加载失败 | 页面级错误提示 | 提供重试或明确说明 |
| 当前页面无权限 | 页面级错误提示 | 不渲染伪正常页面 |

### 19.3 确认文案规则

- 单条删除建议模板：`确认删除该{对象名}吗？删除后不可恢复。`
- 批量删除建议模板：`确认删除选中的 {数量} 条{对象名}吗？删除后不可恢复。`
- 会影响登录、权限访问、系统行为的启用/停用操作，应使用二次确认。
- 普通启用/停用若不涉及明显风险，可直接执行后以 message 反馈。

### 19.4 错误文案规则

- 错误文案应说明发生了什么，以及用户可采取什么动作。
- 避免直接展示后端异常堆栈、接口路径、技术错误码，除非该页面明确面向开发或运维人员。
- 不允许只用“操作失败”而没有任何上下文说明，除非该错误已经在字段级中明确定位。

## 20. 空状态、加载与页面状态规范

### 20.1 空状态

- 空状态文案应简洁，如“暂无数据”“暂无角色”“暂无可授权资源”。
- 仅在必要时补充说明，不堆叠过多描述。
- 搜索无结果与初始无数据可使用不同文案，但风格必须统一。

### 20.2 加载状态

- 表格、抽屉主体、角色列表等局部区域应优先支持局部 loading。
- loading 不应阻断整个页面，除非确实是全局加载。
- 提交中按钮必须进入 loading 或禁用态。

### 20.3 错误状态

- 页面主数据加载失败时，应在主内容区给出明确错误提示和重试入口。
- 浮层内数据加载失败时，应留在当前浮层内处理，不让用户回到页面重新猜测。
- 权限不足、依赖数据缺失、网络失败等错误原因应在文案上有所区分。

## 21. 可访问性基础规范

- 可点击元素应有足够点击区域，不应只依赖极小图标触发操作。
- 图标按钮必须提供 `title`、`aria-label` 或等价说明。
- `focus` 状态必须可见，尤其是输入框、按钮、下拉框、菜单项。
- 禁用态不能只依赖颜色区分，还应通过透明度、鼠标样式和不可点击行为共同表达。
- 表单错误应显示在字段附近或表单显著区域，不能只通过颜色暗示。
- 文本与背景必须保持足够对比度，避免浅灰文字在浅色背景上不可读。
- 弹窗和抽屉打开后，应优先把焦点带到标题、首个可输入字段或主要操作区域。
- 弹窗和抽屉关闭后，焦点应尽量回到触发入口。
- `Esc` 关闭行为必须和未保存内容拦截规则保持一致。

## 22. 响应式与断点规范

### 22.1 设计断点

- 桌面端：`>= 1280px`
- 平板端：`768px - 1279px`
- 手机端：`< 768px`

当前样式实现中还存在 `640px` 的进一步收敛点，主要用于分页、查询区和按钮纵向堆叠。

### 22.2 查询区响应式规则

- 桌面端：3 到 4 列。
- 平板端：2 列。
- 手机端：1 列。
- 搜索、重置、展开/收起按钮在窄屏下允许换行或独占一行。

### 22.3 表单响应式规则

- 两列表单在平板端和手机端应收敛为单列。
- 标签、输入控件、错误提示不能被压缩到不可读。
- 长路径、长编码、技术字段在窄屏下允许换行或省略，但必须可查看完整内容。

### 22.4 表格与操作列响应式规则

- 桌面端保持标准 Excel 风格管理列表布局。
- 窄屏优先使用横向滚动，不强制压缩所有列。
- 表格列宽在响应式变化后仍必须稳定，不得因数据内容变化抖动。
- 选择列、关键识别列和操作列应优先保证可读性。
- 操作列必须固定宽度，按钮文字不换行。
- 列较多时，支持左侧冻结关键列、右侧冻结操作列。
- 操作列在横向滚动时必须冻结在右侧。
- 表格滚动区域必须预留水平和垂直滚动条位置，避免滚动条出现造成布局抖动。
- 单元格长文本在窄屏下可按列配置为截断、换行或保留横向滚动，但策略必须由列定义明确指定。
- 操作列在空间不足时，可更积极地收敛到 `更多`。
- 权限可见性和业务禁用态规则不因响应式布局变化而改变。
- 如未来确需为某些关键列表提供卡片式移动布局，必须作为例外登记，不作为默认规范。

### 22.5 抽屉与 footer 响应式规则

- 桌面端抽屉按内容复杂度使用固定宽度档位。
- 平板端可使用更大比例宽度。
- 手机端抽屉应接近全屏宽度。
- 桌面端 footer 按钮右对齐。
- 窄屏下按钮可纵向堆叠或全宽展示，但顺序保持一致。

## 23. 图标规范

- 图标优先使用现有 `Bz*` 图标组件或统一内联 SVG。
- 同类行为图标应统一，不允许同项目中多套相同语义图标并存。
- 树形展开/收起、搜索、刷新、关闭、更多等高频图标应保持统一来源。
- 不建议在管理后台中混入品牌感过强或风格不一致的第三方图标集。

## 24. 组件复用规范

优先复用：

- `AdminEntityDrawer`
- `AdminActionBar`
- `AdminTableTools`
- `BzButton`
- `BzInput`
- `BzSelect`
- `BzTable`
- `BzPagination`
- `BzSwitch`
- `BzCheckbox`
- `BzTag`
- `BzLoading`
- `BzEmpty`
- `BzDialog`
- `BzAlert`

要求：

- 禁止页面内重复发明新风格按钮、新风格抽屉、新风格表格交互。
- 新增能力优先扩展通用组件，而不是在单页硬写一套特殊实现。
- 页面级样式应优先建立在通用组件既有语义类之上，而不是绕过组件直接拼原生元素。

## 25. 文案规范

### 25.1 文案克制与说明文字规则

- 后台页面应保持简单、干净、可扫读，避免展示业务无关的说明文字。
- 页面、抽屉、弹窗、卡片分组、表格区域默认不展示说明性副文案。
- 说明文案只有在能帮助用户理解业务规则、操作限制、数据含义、风险后果或复杂交互方式时才允许展示。
- 禁止展示重复标题含义、描述页面结构、描述实现方式、与当前操作无直接关系的泛化说明文案。
- 如果删除某段说明文字后，用户仍能准确理解当前区域的用途和可执行操作，则该说明文字应删除。
- 必要说明应简短、具体、业务相关，不得堆叠多句说明。

### 25.2 通用文案规则

- 动作标题简洁直接，如“新增资源”“编辑资源”“用户维护”。
- 操作文案统一使用动词，如“详情”“编辑”“删除”“新增子项”“关闭”“保存”。
- 空状态、提示文案避免口语化和情绪化。
- 不在抽屉标题中拼接业务字段。
- 搜索、筛选、确认、错误文案必须明确业务对象，避免歧义。

## 26. 开发与评审检查清单

页面开发完成后，至少应按以下清单自查和评审：

- 页面是否遵循标准后台页面结构。
- 是否复用 `Bz*` 组件和项目已有后台组件。
- 是否避免在单页硬编码特殊颜色、阴影、圆角和按钮样式。
- 管理列表是否采用 Excel 风格结构，而不是割裂的多卡片结构。
- 查询区是否默认收起，并通过同一个搜索 icon 按钮打开 / 关闭。
- 查询区字段、按钮顺序和查询后回到第 `1` 页的行为是否统一。
- 工具栏左侧是否为业务文字按钮，右侧是否为查询 icon 按钮。
- 业务操作过多时是否通过统一 `更多 / 收起` 能力收敛。
- 批量操作是否进入二阶段批量模式，并隐藏其它普通业务操作。
- 批量模式下是否显示提示、已选数量、确认和取消。
- 批量模式是否显示预留选择列中的复选框，且不造成数据列右移。
- 表格是否始终预留选择列宽度。
- 表格列宽是否固定，翻页、筛选、刷新、空值和长文本是否不会导致列宽变化。
- 是否最多只有一个弹性列占用剩余宽度。
- 操作列宽度是否固定，是否优先保证按钮可读，不被其它列挤压。
- 操作列按钮文字是否不换行。
- 表格是否支持单元格溢出策略，如截断、换行、`pre-wrap`。
- 截断内容是否提供可选择、可复制的完整内容浮层。
- 多列场景是否支持横向滚动。
- 关键列和操作列是否按需要冻结，操作列是否必须冻结在右侧。
- 所有可能出现滚动条的区域是否预留滚动条位置，避免页面抖动。
- 表格列内容、空值、长文本、省略、tooltip 是否符合规范。
- 表格操作列是否使用统一操作条或统一规则。
- 操作列是否满足“小于等于 3 个全直出，大于 3 个前 2 个直出，其余进入更多”。
- 无权限操作是否隐藏。
- 有权限但业务不可用操作是否禁用。
- 禁用态点击是否无任何业务副作用。
- 危险操作是否使用红色语义并进行二次确认。
- 分页列表是否使用统一分页区域，翻页时列宽是否稳定。
- 树形列表是否保持表格结构、稳定缩进和固定操作列。
- 表单必填、校验、错误提示、提交 loading 是否完整。
- 抽屉和弹窗标题、内容分组、footer 按钮是否符合规范。
- 详情页和编辑页中的只读信息区是否使用统一详情表格，而不是独立字段卡片堆叠。
- 详情分组内字段是否满足列对齐、跨列补齐、空值占位和长文本撑高规则。
- 保存成功、删除成功、操作失败等反馈是否符合规范。
- 空状态、加载态、错误态是否完整。
- 响应式布局是否在桌面端、平板端、手机端具备基本可用性。
- 文案是否使用统一动词和业务命名。
- 页面是否存在需要登记的业务特殊例外。

## 27. 禁止事项

- 禁止在后台页面中引入不一致的 UI 框架。
- 禁止在标题区堆叠业务标识信息。
- 禁止在同一后台中出现多套不同操作按钮规则。
- 禁止大量使用无意义说明文字占据视觉空间。
- 禁止通过颜色滥用表达层级。
- 禁止把无权限操作做成禁用态。
- 禁止把可禁用的业务操作直接随意隐藏。
- 禁止同类页面出现明显不同的表单、抽屉、详情布局模式。
- 禁止为了单页赶工绕开通用组件体系直接复制粘贴一套新交互。
- 禁止管理列表页将筛选区、工具栏、表格和分页拆成割裂的大卡片。
- 禁止搜索打开和关闭使用两个并列按钮占用两个位置。
- 禁止表格列宽依赖当前页内容自动变化。
- 禁止翻页、刷新、筛选、批量模式切换时导致列宽抖动。
- 禁止操作列按钮换行或被其它列挤压到不可读。
- 禁止不预留选择列宽度导致进入批量模式时整表右移。
- 禁止不预留滚动条位置导致内容出现横向或纵向抖动。
- 禁止为了冻结列拼接两套不同表格并同步滚动。

## 28. 未来演进建议

后续如继续演进 `web-admin`，建议把本规范逐步沉淀为以下可复用资产：

- 通用页面模板
- 通用 Excel 风格管理列表组件
- 通用管理列表工具栏组件
- 通用可收起筛选区组件
- 通用业务操作收敛组件
- 通用批量操作二阶段组件
- 通用固定列宽表格能力
- 通用冻结列能力
- 通用可复制溢出 tooltip 组件
- 通用详情分组组件
- 通用详情表格组件（Excel 风格）
- 通用后台表单网格组件
- 通用状态展示组件
- 通用树节点展开图标组件
- 通用禁用操作样式规范
- 通用抽屉标题与 footer 规范
- 通用字段级校验展示能力
- 通用页面级错误态组件

## 29. 结论

`web-admin` 的 UI 不追求花哨，而追求：

- 页面清晰
- 分组明确
- 操作统一
- 信息可扫读
- 高密度但不混乱
- 可持续扩展

后续所有后台页面新增、调整、重构、评审和验收，都应以本规范为准，优先保持全局一致性，再考虑局部个性化实现。若确有特殊业务页面，必须先走例外登记机制，而不是在单页自行发明新规则。
